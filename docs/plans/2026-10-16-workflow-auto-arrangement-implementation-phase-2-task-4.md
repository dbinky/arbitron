## Seed operation

1. Source.List and Ledger.Seeded identify candidates. Read malformed samples logs a warning and skips only that sample; infrastructure failures abort the seed pass. Already-seeded names are untouched, including never stamping pre-feature samples on startup.
2. Acquire the shared destination mutation lock; re-read ledger/publication and settle prior prepares inside it. Two processes racing the same new sample must not create two authoring revisions. Ledger alone is not commit proof.
3. A fresh sample's source Presentation is untrusted. Assign final shared workflow ID/name, stamp and durably record prepared input BEFORE Registry.Register, tree intent and the first visibility write. Prepare durable tree intent before replacing any existing proven seed tree. Write all supporting files under the same operation lock before publication proof and receipt. Use staged tree materialization where available; readers taking the same lock cannot observe a partially seeded sample.
4. Route exact final publication through P2T3 WriteAndRecord.PreparedPublication → CommitPublication. Store matching revision/ID atomically. On failure restore old tree (or remove a fresh target), then Abandon only after successful rollback. On rollback failure retain request/intent for Settle and surface both errors. Never overwrite an unrelated same-name folder simply because Exists returned true.
5. After exact publication proof, Committed writes receipt then requests work. Enqueue/receipt outage keeps durable evidence; the committed seed still succeeds. Record the seed ledger only after content/publication commit. If the ledger write fails, restart verifies exact destination/publication commit proof, calls RevisionStamper.EnsureStamped for that proven committed seed, preserves its graph/token/time, then Committed requests it idempotently. If the journal was already ack-cleaned, EnsureStamped uses P2T5 Requester.AcknowledgedArrangement, subject to the exact seed-only input checks in contracts §6.18. Rewriting an old journal entry must not downgrade a committed receipt.
6. Recovery of a prepare without exact seed publication is rollback/quarantine, not blind adoption. A later seed pass may make a genuinely new authoring attempt from its source, with a new token; it must not arrange the failed attempt. Committed history survives even if the source sample later changes.
