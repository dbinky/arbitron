# Remote Runners — Phase 3 Task 3: Workspace homes and the single-writer resource lease

## Resolution amendment — RR-08 non-portable homes (decision 2026-11-22)

Decision (recorded in P3 T2 "Portable Git producer" and the Phase 3 design RR-08 row): Arbitron never fetches promisor objects over the network. A run whose repository has required promisor objects missing locally gets a **non-portable home**: it is pinned to the built-in runner, excluded from remote placement and load moves, and its steps keep running on the built-in runner as today, with no step failure. The marker clears automatically when a later built-in checkpoint attempt finds all objects present. Partial clones are a Non-Goal for remote execution. This amendment is authoritative over conflicting text below.

**This task (producer of the marker):**
- `domain/runner/homes.go`: `Home` gains `NonPortableReason string` (`""` = portable; JSON `nonPortableReason`). Add `const NonPortablePromisorReason = "partial clone: required promisor objects missing locally; use a full clone or run git fetch --refetch"`.
- `HomeStore` gains `SetNonPortable(ctx context.Context, runID uuid.UUID, reason string) error`. A non-empty reason upserts the row (creating `{RunID, RunnerID: ServerHome}` if absent) without changing owner, generation, checkpoint version or dirty. `""` clears it. It is idempotent and writes no `home_moves` row.
- `WorkspaceHomeRepo` reads/writes `workspace_homes.non_portable_reason` (column added by P3 T1 migration 044); `loadHomes`/`GetHome`/`ListByRunner` populate the field, so `PoolSnapshot.Homes` carries it to P3 T4 `Place`.

## Alignment repair — required replacement work (2026-11-20)

**Location is not a writer lease.** Keep `HomeStore` as the location/history API, but retire the claim that same-owner `AcquireResource` provides exclusive execution. Add a required durable writer port in `domain/runner/resource_lease.go`:
```go
type ResourceLeaseStore interface {
 Claim(ctx context.Context, key, holder string, owner RunnerID) (engine.ResourceFenceRef, error)
 Check(ctx context.Context, f engine.ResourceFenceRef) error
 Release(ctx context.Context, f engine.ResourceFenceRef) error
 Supersede(ctx context.Context, old engine.ResourceFenceRef, holder string, owner RunnerID) (engine.ResourceFenceRef, error)
}
```
`engine.ResourceFenceRef` is `{Key string; Owner string; Generation int64; Token uuid.UUID}`. `holder` is the durable operation identity (`invocation/operation/attempt` or group mutation ID), and run workspaces use `run:<uuid>`. `adapter/sqlite/resource_lease_repo.go:ResourceLeaseRepo` implements it over 044 `workspace_leases`. `Claim` atomically fails `ErrResourceBusy` for any active holder, including another job on the same runner; each new claim gets a new random token and increments generation. The same holder may recover its exact existing claim only after verifying its durable operation/job identity. There is no TTL-based ownership transfer: suspect grace must not be bypassed.

`Supersede` is an internal recovery transaction only after the old job is fenced for confirmed runner loss/revocation, or cancellation plus confirmed process stop; it verifies the entire old token/generation. `Release` is also token/generation checked and cannot release a newer writer. `MarkDirty` and `SetCheckpoint` may not be invoked as independent unfenced progress writes: P3 T5/T6/T13 transactions own those changes together with the resource lease.

P3 T13 builds one `NewResourceLeaseRepo(db)` and passes it to workspace sync, group resource, recovery, transfer token issuer and committers. Before implementation add `TestResourceLease_SameRunnerWritersCannotOverlap`, `TestResourceLease_ConcurrentClaimHasOneWinner`, `TestResourceLease_StaleReleaseCannotClearNewOwner`, `TestResourceLease_SuspectDoesNotAuthorizeSupersede`, `TestResourceLease_StorageErrorNeverGrantsOwnership`.

**Goal:** Implement `runner.HomeStore` over SQLite so every run's workspace has exactly one owning runner (its home) guarded by an expected-generation CAS, with a move history row for every handoff, and expose homes in `Registry.Snapshot`.
**Architecture:** `workspace_homes` (migration 041, P1 T5) holds the current owner/generation/checkpoint version/dirty flag; `home_moves` (044, P3 T1) is the append-only history. Each mutation is one SQLite transaction (`SetMaxOpenConns(1)` ⇒ single writer) with a `WHERE generation = ?` CAS. The repo never reacts to liveness: a suspect home keeps ownership until a caller (dispatcher/recovery) hands it off after loss. Events (`workspace.moved`) are emitted by the sync service (P3 T6), not here.
**Tech Stack:** Go 1.25.5, hand-written SQL (pattern `adapter/sqlite/audit_repo.go`), modernc SQLite, testify.
**Spec / Design:** spec "Recovery and session continuity" (one active execution owner); design phase 3 §3.1 (homes, generation, history, exactly one writer, suspect keeps ownership), §5 row "Home/resource identity, lease/generation, ownership and move history" (RR-08), §8 ("two workspace writers cannot overlap", "suspect homes do not move before loss"). Contracts: `docs/plans/remote-runners/2026-11-20-contracts.md` §16 (Homes), §7 (`Home`, `PoolSnapshot.Homes`), §8 (`Registry.Snapshot`).

Semantics:
- `AcquireResource(owner)`: current owner == `owner` ⇒ returns the home unchanged (idempotent, no bump). No row or owner `""` ⇒ becomes `owner`, generation+1, history `{From:"", To: owner, Reason:"acquire"}`. Different owner ⇒ `ErrHomeOwned`. Generation ≠ `expectGen` ⇒ `ErrHomeGenerationConflict`.
- `HandOff(to)`: CAS on `expectGen`; `to` == current owner ⇒ unchanged; otherwise owner=`to`, generation+1, `dirty=0` (the new owner starts from the committed checkpoint), history row with reason/bytes.
- `adapter/sqlite/workspace_home_repo.go:WorkspaceHomeRepo` — `func NewWorkspaceHomeRepo(db *sql.DB) *WorkspaceHomeRepo`; package helper `func loadHomes(ctx context.Context, q interface{ QueryContext(context.Context, string, ...any) (*sql.Rows, error) }) (map[uuid.UUID]runner.Home, error)` used by `RunnerRegistryRepo.Snapshot`.

// Two workspace writers cannot overlap: N concurrent handoffs with the same
// expected generation produce exactly one winner (file-backed DB, real tx).
func TestWorkspaceHomeRepo_ConcurrentHandOffSingleWinner(t *testing.T) {
	ctx := context.Background()
	db, err := Open(filepath.Join(t.TempDir(), "homes.db"))
	require.NoError(t, err)
	t.Cleanup(func() { db.Close() })
	require.NoError(t, RunMigrations(db))
	repo := NewWorkspaceHomeRepo(db)
	run := uuid.New()
	_, err = repo.AcquireResource(ctx, run, runner.BuiltInRunnerID, 0)
	require.NoError(t, err)

	const writers = 12
	var wg sync.WaitGroup
	var mu sync.Mutex
	wins, conflicts := 0, 0
	for i := 0; i < writers; i++ {
		wg.Add(1)
		go func(i int) {
			defer wg.Done()
			_, err := repo.HandOff(ctx, run, runner.RunnerID(fmt.Sprintf("mac-%d", i)), "should_move", 0, 1)
			mu.Lock()
			defer mu.Unlock()
			switch {
			case err == nil:
				wins++
			case errors.Is(err, runner.ErrHomeGenerationConflict):
				conflicts++
			default:
				t.Errorf("unexpected error: %v", err)
			}
		}(i)
	}
	wg.Wait()
	assert.Equal(t, 1, wins)
	assert.Equal(t, writers-1, conflicts)
	h, err := repo.GetHome(ctx, run)
	require.NoError(t, err)
	assert.Equal(t, int64(2), h.Generation)
	hist, err := repo.History(ctx, run)
	require.NoError(t, err)
	assert.Len(t, hist, 2, "exactly one handoff recorded")
}

## Recovery base — DECISION RR-17: B

**DECISION (2026-11-22) RR-17: B** (contracts §22/§24; owner P3 T16, `2026-11-20-phase-3-task-16.md`). A non-portable home takes a **local checkpoint** after each workspace-changing step completes: a plain copy of its directory on the server's own disk, with no portable-Git materialization. The step transaction commits it as `workspace_homes.local_checkpoint` via `WorkspaceCompletion.LocalRef`, and only the latest committed copy is kept. PoolRecovery restores it and re-runs the interrupted step under the same fences. With no local copy, recovery uses the home's initial state. With no base at all, `runner.ErrNoRecoveryBase` produces the durable `job.recovery_blocked` blocker. **This task:** P3 T16 adds `Home.LocalCheckpoint string` and `HomeStore.BootstrapLocalCheckpoint(ctx, runID, ref string) error` to the types declared here, and extends `WorkspaceHomeRepo` (`loadHomes`/`GetHome`/`ListByRunner` read `local_checkpoint`). Every `HomeStore` fake and decorator implements the new method.
