# Remote Runners — Phase 4 Task 6: Atomic session/workspace turn checkpoints


**Spec / Design:** `docs/specs/2026-11-19-remote-runners-spec.md` (Recovery and session continuity); `docs/designs/2026-11-19-remote-runners-design-phase-4.md` §3.2, §3.3, §3.6, §7–8; shared `docs/plans/remote-runners/2026-11-20-contracts.md` §16–17, §20–21.

**Goal:** A successful turn is durable only when its exact session bundle, workspace candidate (when mutable), messages, accepted binding, pin, intent and every dispatched completion commit together. Artifact upload never advances the committed workspace pointer. A crash retains the previous complete pair.

**Prerequisites:** P1 T2/T8/T14 identity/placement and dispatcher; P3 T1/T2/T3/T6/T9/T10 atomic candidate and resource ownership contracts; P4 T1/T2/T3/T4/T5. Consumers: P4 T8/T9/T10/T11/T12/T13. Read contracts §16–17; use the shared `StepCompletion`, `WorkspaceCompletion` and `ResourceFenceRef` names without local substitutes.

**Retired instructions:** The previous lease-only `TurnCommit`, `turnRunner` selecting the last placement fact, `CheckpointStore.Latest` as a remote turn receipt, `CheckpointStore.Commit` as staging, and `PublishTurn`/`HomeStore.SetCheckpoint` after the DB transaction are removed. No implementation or fixture may preserve those paths.

## Transaction and call order

1. First turn and every later turn already hold P4 T2's lease and P4 T3's durable intent. Install operation-scoped placement and completion sinks before the decorated stream call. Resolve the effective backend before acceptance. Require valid invocation, intent, lease token and exact completion receipt in production; missing provenance returns an error before any success event/advance. Legacy unit tests explicitly supply memory stores and receipts.
2. Consume the successful stream's receipt. Its job is still commit-pending, fenced and resource-owned until `CommitTurn`. Export the harness bundle from that receipt's runner, validate backend/session/workdir identity, checksum and size, then store it. Stateless API chat has no native bundle; its transcript is still committed and its stream job is still fenced.
3. For a mutable session, validate and reuse the already-prepared workspace under the SAME job/resource receipt. The dispatcher retains P3 WorkspaceAttempt from BeginAttempt through the stream; on terminal success it calls FinishSuccess (builtin StageBuiltIn / remote exact pushed candidate), records the full receipt before forwarding Done, and never prepares twice. StageTurn checks candidate, job, resource and manifest agreement. Never discover it through Latest, a home version, or a runner-global last result. Resolution staging uses its own resource, P4 T11.
4. Pass the candidate's `WorkspaceCompletion` in the stream `StepCompletion` to `CommitTurn`. One SQLite transaction validates intent invocation/turn, lease token and generation, every current job fence, resource owner/token/generation and open-session CAS; inserts/updates the execution; advances the authoritative committed resource pointer; attaches the workspace and session refs plus accepted binding and ConversationKeyTurnIdentity (from exact committed intent/lease); updates pin/generation; completes the exact intent and jobs. A missing/empty fence or candidate rejects the whole transaction. `setSessionStateTx` alone is not the ownership boundary.
5. Only after commit publish the assistant message or ended event, release execution slots/resource ownership, and let the engine/gather continue. No later fallible pointer publication exists. P4 T11 materializes the committed staging checkpoint before gather verification, with a durable retry if that local copy fails. A sentinel follows this same gate.
6. End/Abandon without a new stream use their durable operation intent and held lease plus the already committed pair; completion/state transition remains idempotent and fenced. They never manufacture an empty stream fence. A turn write failure keeps the prior pair and a retryable intent; no assistant success leaks.

## STRICT TDD cycles

For each cycle: write named tests, run the focused command and observe the intended assertion/undefined-symbol failure, implement minimum production code, rerun green, then refactor while green. A compile failure establishes an absent interface only; behavior tests must then fail on the intended invariant before the fix. All five categories are required; do not hard-code test counts or use a pipeline that hides a failing test exit status.

1. **Identity and engine checkpoint gate** — `go test ./domain/engine -run 'SessionCheckpoint|TurnCheckpoint' -count=1`.
   - Happy: first and later agent turns export/store/stage/commit in order, including sentinel.
   - Success: stateless chat commits transcript and job without fabricating a bundle.
   - Failure: export/checksum/stage failure emits no assistant success and leaves intent pending.
   - Error: nil exporter/committer, missing identity/empty receipt, unknown backend reject before dispatch or commit.
   - Edge: concurrent export job cannot replace the stream receipt; loop visit uses a new invocation; group staging never uses parent's resource.
2. **Filesystem bundle and prepared local candidate validation** — `go test ./adapter/checkpoint -run 'Session|TurnStage' -count=1`.
   - Happy: bundle roundtrip and a prepared directory candidate restored on a second store.
   - Success: retention keeps current committed pair and exactly the configured old refs.
   - Failure: bad checksum/path/symlink/size is refused without partial install.
   - Error: disk full and rename failures leave committed Latest unchanged.
   - Edge: crash after candidate upload leaves old Latest; GC preserves in-flight and committed refs and reclaims only expired orphans.
3. **Runner receipt routing** — `go test ./domain/runner -run 'SessionExport|TurnWorkspace|SessionPortability' -count=1`.
   - Happy: builtin export uses local registry; remote export goes to the receipt's runner.
   - Success: local staging preserves old pointer; remote staging consumes exact pushed candidate.
   - Failure: mismatching resource/job/generation/session/backend is rejected.
   - Error: missing remote exporter or missing prepared stream receipt fails closed.
   - Edge: old remote candidate and two same-run uploads cannot substitute for current receipt.
4. **Atomic SQLite commit** — `go test ./adapter/sqlite -run 'TurnCommit|NodeExecution.*Session' -race -count=1`.
   - Happy: all writes become visible in one transaction.
   - Success: exact idempotent retry returns committed outcome without duplicate transcript/intent/events.
   - Failure: old job, resource, lease token, session generation or closed group session rolls back all writes.
   - Error: inject failure at each statement (execution, pointer, session state, intent, job completion); no half pair and no slot release.
   - Edge: crash after SQL commit before response replays the committed result; same-generation older-turn retry cannot overwrite a newer turn.
5. **Actual engine consumers** — `go test ./domain/engine -run 'ConversationHandler.*Checkpoint|InteractiveExecutor.*Checkpoint' -race -count=1`.
   - Happy: first/later turns and terminal sentinel keep exact matching refs.
   - Success: frontend success only after durable commit.
   - Failure: failed commit keeps original transcript/pin/pair, allows durable replay.
   - Error: missing placement/completion producer is an explicit error (no builtin default).
   - Edge: resumed/adopted turn uses original receipt and original invocation, with zero re-dispatch.

Final package gate: `go test ./domain/engine ./domain/runner ./adapter/checkpoint ./adapter/sqlite ./adapter/runner/... -count=1`; `go vet ./domain/engine ./domain/runner ./adapter/checkpoint ./adapter/sqlite`. P4 T13 owns full binary/root tests. Do not implement other tasks here or create a second transaction owner.
