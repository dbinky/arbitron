# Remote Runners — Phase 3 Task 2: Immutable checkpoint artifacts and prepared candidates

**Goal:** Produce recoverable, immutable tar+gzip artifacts with verified manifests and portable Git metadata. A prepared artifact becomes committed progress only through the validated step/resource/turn transaction; uploading bytes never changes the recovery base.

**Spec/design:** remote-runners spec Recovery and session continuity; Phase 3 design §3.3, §5, §7, §8; shared contracts §8 and §16. Depends on P3 T1 migration 044 and P1 ledger fence. P3 T3 writer lease and P3 T5 commit contract are peer contracts declared before implementation. This task replaces the previous checkpoint plan in full; immediate latest-row publication and nil-fence built-in success are removed.

## Candidate and publication semantics

- `StageBuiltIn` and `Publish` fsync complete artifact data before registering `CheckpointCandidate`. `CheckpointCatalogRepo.Publish` validates exact active job/resource fences and committed base in one SQLite transaction, then inserts `state='prepared'` with both fences. Inserting a row does **not** update `workspace_homes.checkpoint_version` or clear dirty.
- `Latest` resolves that authoritative committed pointer and requires the row to be committed. No `ORDER BY version DESC` query may substitute for the pointer. Prepared artifacts remain queryable by exact trusted operation for validation, never through a normal pull/recovery `Latest`.
- `Commit` is bootstrap only, called by P3 T6 `WorkspaceBaselineInitializer.EnsureBaseline` through `Engine.prepareWorkspace` before dispatcher intent/reservation/resource claim: `Bootstrap` atomically verifies no prior committed checkpoint and no active other job/resource lease, then records the baseline. It must not be used for successful dispatched steps, server group mutations or interactive turns. A first `BeginAttempt` requires this baseline and cannot create it after claiming. Group branch `ForkTask` must finish before the child baseline hook runs. P3 T5's step transaction, P3 T13's resource transaction, and P4's turn transaction perform their respective progress publication.
- Candidate version allocation must be unique transactionally even under concurrent preparation/retried requests. A matching idempotency identity returns the same candidate. Ref/job/resource/base mismatch is a conflict. Abandoned versions may leave gaps.
- Preserve the prior artifact until durable result/continuation publication. Crash after artifact creation leaves an unreferenced artifact; crash after prepared insertion leaves a prepared row; neither changes recovery base. Garbage collection prunes only unreferenced expired artifacts, never committed/replay refs or active candidates.

## Archive and manifest safety

Sort normalized relative paths; include file modes, directories, symlinks, deletions and required Git data in deterministic hashing. Reject absolute/traversal/backslash/empty paths and unsupported devices/sockets/FIFOs. Validate symlinks stay contained, bound decompressed bytes/entry count/path lengths, and reject duplicate archive names, unexpected trailing parts and hash/manifest mismatches. Extract through `os.Root` into a private staging tree; no symlink traversal into execution or checkpoint roots. Verify every changed file's declared size/hash and full resulting manifest before candidate preparation. A failed/partial restore stages before swapping at a safe ownership boundary and leaves the prior recoverable artifact intact.

`ReadFile` opens only a manifest-listed regular file from the exact referenced immutable snapshot. It never serves a mutable work dir or follows a link outside that snapshot. `StageDelta` applies declared deletions and changes to the pinned committed base in private staging, verifies the full next manifest and does not mutate the base.

## Portable Git producer

`adapter/checkpoint/git.go:MaterializePortableGit` operates only on a PRIVATE checkpoint copy, preserving the user's original working tree/repository. Resolve linked-worktree common metadata and materialize self-contained object/ref/index data; preserve dirty/untracked files, executable bits, HEAD/ORIG_HEAD/MERGE_HEAD, reflogs and unmerged index stages. Compute the full required object closure including index stage objects, not `--all` refs alone. Repack alternate objects into private storage using Git with lazy network fetch disabled (`GIT_NO_LAZY_FETCH=1`), verify object reachability/closure there, then remove private alternates/gitdir backlinks. Verify restore with the original repository removed and network disabled. Do not copy external paths as dangling metadata. P4 T11's resolution portability adapter reuses this helper, so merge/conflict state has the same fixture contract.

Alternates that can be materialized locally are supported; auto-repacking the user's repository is neither necessary nor authorized by this task. A partial/promisor repository with genuinely missing required objects returns `ErrUnsupportedGit` identifying the unsupported object cause, preserving prior progress. It cannot silently complete in-place without a recoverable snapshot.

**DECISION (2026-11-22, RR-08):** Arbitron never performs a network fetch to build a checkpoint (Git runs with `GIT_NO_LAZY_FETCH=1`; no `git fetch`, no credential helper). Partial-clone/promisor repositories are a **Non-Goal for remote execution**. When required promisor objects are absent locally, `MaterializePortableGit` returns an error wrapping `ErrUnsupportedGit` **and** the new sentinel `ErrPromisorObjectsMissing` (declared in `domain/runner/checkpoint.go` beside `ErrUnsupportedGit`), and `StageBuiltIn`/`Commit` propagate it unchanged without registering any candidate. This is **not** a step failure: the consumer P3 T6 `WorkspaceSync` (`EnsureBaseline` and `CommitBuiltIn`) treats `errors.Is(err, ErrPromisorObjectsMissing)` by calling the P3 T3 producer `HomeStore.SetNonPortable(ctx, runID, NonPortablePromisorReason)` and continuing in built-in-only mode (today's behaviour: the built-in `{{workspace}}` working copy stays the recovery base, no checkpoint is created for that step). `NonPortablePromisorReason` is the exact visible string "partial clone: required promisor objects missing locally; use a full clone or run git fetch --refetch" (declared in `domain/runner/homes.go`). P3 T4 `Place` pins such a home to the built-in runner (`AffinityBuiltIn`) and excludes it from remote placement and load moves. The marker clears automatically: the next successful `StageBuiltIn` for that run (all objects present) produces a normal candidate, and P3 T5 clears `non_portable_reason` in the same transaction that promotes it. Full non-portable semantics (baseline exception, no restore, `NonPortable` completion receipt, recovery) are specified in the RR-08 amendments of P3 T1/T3/T4/T5/T6/T10. Other `ErrUnsupportedGit` causes (not promisor) keep their existing visible-failure behaviour.
