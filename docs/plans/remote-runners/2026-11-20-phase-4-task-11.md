# Remote Runners — Phase 4 Task 11: Portable group-resolution staging resources


**Spec / Design:** `docs/specs/2026-11-19-remote-runners-spec.md` (Recovery and session continuity); `docs/designs/2026-11-19-remote-runners-design-phase-4.md` §2 Group sessions, §3.4–3.6, §7–8; shared `docs/plans/remote-runners/2026-11-20-contracts.md` §16–17, §20–21.

**Goal:** Conflict-resolution first turns, later turns, end/abandon and recovery use one durable resolution identity and a separately owned staging resource. Exhaustion, logout, drain or confirmed loss can move it to an eligible remote runner; the gather verifies and applies only the committed staged result. Parent/task directories are never checkpoint sources or remote writable mounts.

**Correction:** The former built-in-only implementation, `BuiltInOnly` flag, and tests that accepted waiting while same-group remote capacity existed are retired and removed. RR-11 is implemented by the named producers below; a NOTE or capacity wait cannot substitute for them. Native session import may rebuild visibly when workdir/home changes, as allowed by the spec.

**Prerequisites:** P3 prepared checkpoint/resource lease and transfer contracts; P4 T1–T10. P4 T12 consumes the descriptor, P4 T13 wires both binaries, P4 T14 reads pins. No new migration number: schema additions belong to 045.

## Interfaces and production ownership

Consumes existing `domain/engine/group_resolution.go:GroupResolutionIdentityOf`, `GroupResolutionBridge.StartResolution`, `ResolutionRequest.Handle.StagingDir`, `GatherHandle`, `WorkingArea`; `adapter/git/working_area_merge.go:WorkingArea.BeginGather` produces a staging `.git` with `objects/info/alternates` pointing to server backing objects. A plain tar of staging is insufficient. `sealStaging` already strips unsafe metadata before git operations.

Consumes P4 T2 `ResolutionLeaseKey`, held `turnLeaseHold`; P4 T3 `AcceptedTurnBinding`, exact turn intent; P4 T6 `TurnCommit/TurnWorkspaceRequest` with exact `StepCompletion/WorkspaceCompletion`; P4 T8 mover; P3 `ResourceFenceRef` and prepared candidates. Resource lease key is `resolution:<resourceUUID>`; owner jobs, moves and transfer tokens all carry that identity and generation independently of the parent workspace.

## Portable git algorithm

1. Under the existing gather gate and resolution lease, validate `GroupResolutionIdentity` against the stored gather handle and resolve its trusted staging directory. Prepare a private copy beneath `<workspaceRoot>/.runner-resources/resolutions/<resourceUUID>` on the server; remote roots use the same relative resource path. Do not ask a remote runner to open the server backing path.
2. `WorkingArea.ExportResolution` copies working files, permissions, empty dirs and required `.git` state (index with stages 1/2/3, HEAD/refs, MERGE_HEAD/MERGE_MSG/ORIG_HEAD and objects) into that private copy. Call the P3 helper `adapter/checkpoint/git.go:MaterializePortableGit(ctx, stagingDir, dstDir)` for the complete object closure; add resolution-specific MERGE_HEAD/ORIG_HEAD and every unmerged index-stage object to its root set. The helper materializes verified backing/alternate objects into the COPY and removes alternates there. Do not create a second object-closure implementation. Preserve unresolved index and merge state exactly. Never run clean/smudge hooks or overwrite source `.git`. Validate allowed alternate roots, bound expanded bytes, reject cycles/symlinks/path escapes, seal copied config/hooks and run sanitized git connectivity checks in the copy. A standalone `git rev-parse HEAD`, `cat-file MERGE_HEAD`, `ls-files -u` and merge-base read must work with the server backing tree made unavailable.
3. Register the resolution resource and baseline immutable checkpoint before dispatch. Persist original rendered prompt+nonce+accepted binding, exact invocation and resource ref. Execute first turn in the canonical private WorkDir, with prompt WorkDir rendered to that path. Existing source staging remains the gather's destination; neither parent nor task trees are shipped.
4. Placement is `AffinitySession`: first pin chosen from eligible same-group sources, later pin read by exact session invocation. No built-in override for OperationResolution. P4 T8 recovery fences old job/resource owner before handoff and restores the last COMMITTED resolution checkpoint. P4 T12 transfer routes authorize actual RunID + descriptor resource ID + job/resource generation; runner confines paths to its resource root and validates standalone git state before launching the harness.
5. P4 T6 atomically commits the resource candidate together with bundle, messages, session pin/generation and intent. After SQL commit, `MaterializeResolution` restores that exact checkpoint into the trusted original staging dir under the gather gate, re-seals git metadata, verifies identity/generation, and records materialization completion durably. A crash or disk failure here retries materialization on startup; it does not rerun a committed turn. `StartResolution` returns its session ref and End/sentinel invokes the completer only AFTER this gate. The existing gatherer then checks conflicts and applies/continues through its own WorkingArea API.
6. Mid-turn retry restores the baseline/last committed private copy, discards interrupted edits, reuses exact prompt+nonce or exact user message, and clears old tokens via P4 T9. End/Abandon and recovery hold `ResolutionLeaseKey` and use the recorded resource/identity. Closing or replacing an attempt fences pending materialization so it cannot touch a new attempt.

## Wiring and sinks

| Value / collaborator | Real producer | Composition root and sink |
|---|---|---|
| Identity, original staging path | `GroupResolutionBridge.StartResolution` from `run.ID`, req.MergeIndex/Attempt, trusted GatherHandle | P4 T13 bridge `SetResolutionResources`; test drives real gather conflict, never fixture-injects a resource into final handler |
| Portable git state | `adapter/git/resolution_portability.go:WorkingArea.ExportResolution` (this task) | P4 T13 passes existing WorkingArea into `runner.NewResolutionResources`; runner imports via P4 T12 and same portability adapter |
| Resource registry, lease and refs | `sqlite.ResolutionResourceRepo`, P3 `ResourceLeaseStore`, prepared checkpoint store (this task composes them) | P4 T13 builds once and installs on bridge/handler/mover/transfer; same registry used to validate token resource scope |
| Job descriptor, remote files | bridge/handler's durable resource lookup → dispatcher → P4 T12 wire translators → runner executor | final remote fake harness reads MERGE_HEAD/conflict index; nil descriptor must prevent launch |
| Gather-visible changes | `ResolutionResources.MaterializeResolution` after P4 T6 commit | `StartResolution` return and GroupResolutionCompleter invocation gate on durable materialization; removing wiring fails parent gather result assertion |
