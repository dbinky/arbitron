# Remote Runners — Phase 2 Task 13: Fresh remote health and source-bound quota confirmation

**Goal:** An operator check measures the selected runner now, and an exhausted subscription returns automatically only after confirmation on that exact credential source. No server-local credential, old heartbeat, other same-family source or elapsed timer can make a remote source healthy.

**Spec / Design:** `docs/specs/2026-11-19-remote-runners-spec.md`, Execution and placement and Administration; designs Phase 1 §3.11 and Phase 2 §§3.4/3.7; shared contracts §§12/20/24. Depends on P1 T3/T4/T6/T10/T13/T16 and P2 T1–T12. This task replaces P2 T10's former cached-success ProbeNow policy and P1 T13's built-in-only confirmation implementation once remote execution is enabled. P3 T5 later supplies ProbeCommitter without changing this source policy.

## Observation protocol and merge

P2 T1 Probe/ProbeResult carry RequestID UUID and exact source kind/reference. A remote source report gains optional Observation with the nullable P1 ProbeResult, monotonically increasing ObservationSeq and SampleAgeMs. P2 T9 inventory is the production sampler; P2 T8 sends its last observation in hello/heartbeats and a newly sampled one for an operator probe. Repeating a heartbeat never refreshes observation time. Use monotonic sample age and server receipt, not the runner wall clock.

The hub associates observations with its current admission/session serial and source ID, ignores duplicate/older observation sequences and replies from replaced sessions, validates bounded age, and passes each accepted result to ObserveProbe. A probe response fulfills only its exact pending RequestID/source/session and must be sampled after the request. Offline, unsupported, timeout or canceled probe returns an error with the previous stored health unchanged; it never returns cached success. Probe timeout uses a 10-second bounded context (caller cancellation wins). Register pending request before send; remove it on every completion/cancel/shutdown path. Session replacement/loss cancels its pending checks.

Prevent an auth-only/old observation from undoing a newer classified exhaustion. The monitor serializes outcomes and observations; capacity recovery needs fresh matching-scope ordinaryUsageAllowed=true or a successful exact-source, exact-model confirmation. A global Codex allowed flag cannot clear a separately exhausted model window. Auth-only success clears logout while preserving exhaustion/reset. Combined logout+exhaustion applies both fields and raises one notification. Unknown capacity/headroom/percentages do not prove recovery. Refreshed LastProbeAt is persisted even when health otherwise stays unchanged and is exposed by REST/MCP.

| Remote verifier | local factory/capability rules/binary paths | P2 T9 buildAgent executor.Confirmations, translating OpConfirm; remote scratch and local credentials |
| Successful confirmation/result | exact executing assignment and native model evidence | P1/P2 complete the probe ledger job; P3 T5 ProbeCommitter validates it and releases its slot before monitor recovers the source |
| Observation sequence/age | runner-local inventory sample | real hello/heartbeat/probe mirrors/translator, never synthesized by HTTP DTO |

Nil/typed-nil required verifier or remote-prober wiring fails production initialization. Monitor, hub and runner shutdown cancel/join pending probes/confirmations; no channel/goroutine survives DB close. Remote auth probes spend no tokens or execution slots; OpConfirm reserves exactly one normal slot and obeys source probation single-flight. With the runner full it waits cancellably; it cannot spend tokens elsewhere and then recover the selected source.

## Exact freshness fence and nonblocking liveness

Consume P1 T13 `SourceHealth.Revision uint64` and `ProbeResult.HealthRevision uint64` (declared P1 T3, persisted by P1 T5 runner_sources.revision). Hub.ProbeSource captures the source's revision in its pending request; wire Probe/ProbeResult carry it with RequestID. Hub stamps the accepted ProbeResult from that pending entry, not arbitrary reply data. ObserveProbe may recover capacity only if the revision still matches; a classified outcome that wins during I/O forces a new check. Heartbeat observations are initial/auth/headroom hints and never recover a newer exhausted episode without this correlated check or exact native confirmation. The monitor's periodic remote checks use the remote prober at the normal cadence as well as on operator demand; they never run a server-local credential probe.

Keep slow read-only probes off the heartbeat/liveness loop. P2 T8 handles probe work asynchronously with one bounded in-flight check per source and joined cancellation; its heartbeat job loop keeps sending the actual contact/held jobs. Add RED `TestRemoteProbe_InFlightOldRevisionCannotClearNewExhaustion` and `TestAgent_SlowProbeDoesNotMakeHealthyRunnerSuspect`, then GREEN through real protocol/root fixtures. No invented probe timestamp/revision is an acceptable fallback.
