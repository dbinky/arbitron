# Remote Runners — Phase 3 Task 6: Workspace attempts and exact prepared completion receipts

## Resolution amendment — RR-08 non-portable homes (decision 2026-11-22)

Decision (recorded in P3 T2 "Portable Git producer" and the Phase 3 design RR-08 row): Arbitron never fetches promisor objects over the network. A run whose repository has required promisor objects missing locally gets a **non-portable home**: it is pinned to the built-in runner, excluded from remote placement and load moves, and its steps keep running on the built-in runner as today, with no step failure. The marker clears automatically when a later built-in checkpoint attempt finds all objects present. Partial clones are a Non-Goal for remote execution. This amendment is authoritative over conflicting text below.

**This task (detection producer and attempt consumer).** `ErrPromisorObjectsMissing` comes from P3 T2. The marker is written through P3 T3 `HomeStore.SetNonPortable`.
- `EnsureBaseline`: if the bootstrap store path returns `errors.Is(err, runner.ErrPromisorObjectsMissing)`, call `SetNonPortable(runID, NonPortablePromisorReason)`, then commit a local initial state with P3 T16 `LocalCheckpoints.Bootstrap`. If that fails, preparation fails visibly. No catalog baseline is created, and dispatch proceeds.
- `BeginAttempt` on a home whose `NonPortableReason != ""`:
  - requires the decision's runner to be `BuiltInRunnerID` (any other runner gives `ErrHomeOwned`);
  - does **not** require a committed catalog baseline, and does not restore a clean home: its committed local checkpoint (RR-17 B, P3 T16) matches the working copy. Failure and recovery restore that local checkpoint (see "Recovery base — DECISION RR-17: B" below);
  - still claims the `run:<uuid>` resource and marks dirty.
- `CommitBuiltIn`: when `StageBuiltIn` returns `ErrPromisorObjectsMissing`, call `SetNonPortable` (idempotent) and record no candidate. `FinishSuccess` then returns `WorkspaceCompletion{NonPortable: true, LocalRef: <P3 T16 local checkpoint>, Resource: <exact claim>}`, which P3 T5 commits by promoting the local checkpoint (RR-17 B). When `StageBuiltIn` succeeds for a marked home, the normal candidate flows on, and P3 T5's promotion clears the marker.
- A promisor miss is never a step failure, never a pull/preparation outcome and never an exhaustion signal. The dispatcher never sends a non-portable home to a remote runner (P3 T4).
- STRICT TDD (RED first):
  - `TestBaseline_PromisorMissingMarksHomeNonPortableAndDispatches`;
  - `TestWorkspaceSync_NonPortableAttemptNeverRestores` (the working copy edited after the last commit survives `BeginAttempt`);
  - `TestWorkspaceSync_CommitBuiltInPromisorMissingReturnsNonPortableReceipt`;
  - `TestWorkspaceSync_NonPortableRejectsRemoteRunner`;
  - `TestWorkspaceSync_ObjectsPresentAgainStagesNormalCandidate` (the follow-on T5 promotion clears the marker).

**Goal:** Prepare the right committed workspace under one durable writer claim, execute there, retain a recoverable candidate, and feed its exact identity to the engine's validated commit. Failed/uncommitted edits never become the recovery base.

**Spec/design:** remote-runners spec Recovery and session continuity; Phase 3 design §3.1–§3.3, §3.5, §8. Contracts §7, §8, §11, §16. This replaces the earlier task in full: `FinishSuccess` no longer publishes, `CommitBuiltIn` no longer calls unfenced `Commit`, `AcceptPush` does not advance the home pointer, and no returned checkpoint reference is discarded.

**Dependencies:** P3 T1 schema, T2 prepared candidate store, T3 resource lease, T5 completion sink/transaction. T7 implements tokens declared here; T8/T9 remote execution; T13 root wiring. Preserve hexagonal layering.

## Production flow

0. Before any operation of a run can call dispatcher `EnsureIntent`/`Reserve`, `Engine.prepareWorkspace` calls the injected baseline initializer after `EnsureInstanceDir` and before returning control to the run loop. Existing group setup has already completed `ForkTask` before `StartGroupTask` starts the child engine, so this snapshot includes the branch's initial files/Git state. The initializer returns immediately when a committed baseline already exists; it never snapshots an existing dirty/active run again. With no committed baseline it validates the canonical run directory and calls the bootstrap-only store path before any job/resource claim exists. Catalog bootstrap atomically rejects an active job/lease or competing initialized baseline. Concurrent successful baseline creation is handled by re-reading the committed baseline, never overwriting it. Storage/baseline failure fails preparation visibly and prevents any dispatch.
1. `BeginAttempt` requires an existing committed baseline, validates the assignment and durable invocation/operation/attempt identity; claims `run:<uuid>` with that holder and target owner. Claim is exclusive even for two jobs on one runner. Check home, acquire/handoff only under that claim, and read committed `Base`. Suspect ownership is retained until confirmed loss. Handoff must fence old execution before new restore/execute.
2. `BeginAttempt` never bootstraps after reservation/claim. Missing baseline is `ErrCheckpointNotFound` and no process starts; restore the existing committed base whenever home generation/ref/dirty state does not match, then mark dirty under the exact claim before starting real work. Recovery with an active job and no baseline fails closed instead of snapshotting interrupted edits.
3. For remote execution produce `PullPlan`/tokens pinned to that base and resource. P3 T8 turns it into the workspace descriptor; P3 T9 pulls and verifies. The manifest, file requests and push share the same base/ref, not separate `Latest` calls.
4. Built-in success calls `StageBuiltIn` with exact assignment and resource fences. Remote `AcceptPush` checks the token's exact fence/resource/base and writes a prepared immutable candidate. Neither clears dirty, completes a job nor changes committed home pointer. Idempotent push retry returns the same prepared candidate.
5. `FinishSuccess` finds the candidate for THIS job/resource/base and returns `WorkspaceCompletion{Ref,Resource}`. It rejects missing/empty refs, candidates from another operation, stale resource or merely newer committed checkpoints. `runPlaced` adds the exact job fence to `StepOutput.Completion`; dispatcher records it in the engine's invocation completion sink, and defers `Ledger.Complete`.
6. Engine executor output/schema validation precedes P3 T5's transaction. That sole transaction promotes candidate, job result, variables/continuation and home pointer, clears dirty and releases the exact claim. A zero-exit script returning invalid required JSON has not completed its workspace step.
7. On transport/executor/commit failure discard only this attempt's prepared artifact, restore its previous committed base when local, leave remote copy dirty for next clean restore, and release only the exact failed claim after process stop. Never restore while the old process still writes (P3 T10 stopper). Persistence failure after a durable commit is replayed, not rolled back/re-executed.

`CommitBuiltIn` keeps its name for compatibility but prepares only; it looks up and verifies this operation's exact active resource claim. `AcceptPush` derives scope from the stored token/session; archive data cannot choose its own authority. `WorkspaceBytes` measures committed manifest bytes for remote homes. On sizing error return the conservative over-cap sentinel for optional load moves and record a visible diagnostic; do not fabricate zero bytes. Must/should moves remain allowed by policy.

For a pull/preparation failure exclude that runner for the attempt and requeue with `OutcomePullFailed` without spending workflow retries. Bound exclusions by `MaxPullFailures`/remaining candidates; if capacity vanishes show wait with a reason, not an unbounded tight loop. Do not classify a persistence/lease conflict as subscription exhaustion. Wire outcome vocabulary through P3 T8/T9 protocol validation.

## Recovery base — DECISION RR-17: B

**DECISION (2026-11-22) RR-17: B** (contracts §22/§24; owner P3 T16, `2026-11-20-phase-3-task-16.md`). A non-portable home takes a **local checkpoint** after each workspace-changing step completes: a plain copy of its directory on the server's own disk, with no portable-Git materialization. The step transaction commits it as `workspace_homes.local_checkpoint` via `WorkspaceCompletion.LocalRef`, and only the latest committed copy is kept. PoolRecovery restores it and re-runs the interrupted step under the same fences. With no local copy, recovery uses the home's initial state. With no base at all, `runner.ErrNoRecoveryBase` produces the durable `job.recovery_blocked` blocker. **This task:** this supersedes the RR-08 amendment where they conflict. `SyncDeps` gains `Local LocalCheckpointStore`, and `BaselineDeps` gains `Homes` and `Local`. `FinishSuccess` on a non-portable home returns `WorkspaceCompletion{NonPortable: true, LocalRef: <prepared local ref>, Resource}` from `LocalCheckpoints.Take`; a copy failure returns no receipt, so the step is not done. `FinishFailure` restores the committed local copy. `RestoreBuiltIn` restores it for P3 T10. `EnsureBaseline`'s promisor branch commits a local initial state through `LocalCheckpoints.Bootstrap`. `TestWorkspaceSync_CommitBuiltInPromisorMissingReturnsNonPortableReceipt` is replaced by P3 T16's `TestWorkspaceSync_NonPortableSuccessCarriesALocalCheckpointReceipt`.
