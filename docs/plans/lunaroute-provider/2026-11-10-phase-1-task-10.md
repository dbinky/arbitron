# LunaRoute Phase 1 · Task 10 — Wire the LunaRoute rule into profile save, seed, advance, pin preflight and trigger-time pin capture; surface refusals over MCP

**Dependencies:** P1-T4–T5 and P1-T9.

**Shared contract:** Read [README.md](README.md) for execution order, production provenance and the five-category RED → GREEN → REFACTOR gate. All required coverage/provenance sections below belong to this task's RED/GREEN cycle and commit; read the complete document before Step 1.

**Goal:** Every prospective LunaRoute route is checked by `CheckLunaRouteRoute` (fed the loaded capability table) on the ORIGINAL route provider before the codex carve-out can erase it, LunaRoute selections are pinned-only, agent profiles must name their backend, and the refusal text reaches the MCP author verbatim.

**Architecture:** `ValidatePinRoutes` gains a `caps LunaRouteCapabilities` parameter and runs the LunaRoute block first in its loop. `checkRouteVersions` and `ValidateSelection` thread `caps`; every `ProfileService` call site passes `s.rules` (the `CapabilityRules` injected by `cmd/arbitron/main.go:988`), so save, `revalidatePrepared`, seed, advance and pin preflight all apply it. `adapter/provider/model_snapshot.go:NewModelSnapshotter` gains a `caps` argument; `cmd/arbitron/main.go:1420` passes `capabilityRules` (trigger-time pin capture). `adapter/mcp/tools_profile.go:profileErrorResult` returns `LunaRouteRefusal` text verbatim; the `profile_create/update` `backend` description lists `pi` and the LunaRoute requirement.

**Tech Stack:** Go 1.25, mcp-go, testify.

**Spec:** spec §Model discovery/§Chat and agent workflows/§Failure behavior · **Design:** phase-1 §3.7 (ordering, `revalidatePrepared`, following mode), §5 Deferred "Composition-root wiring"

## Global Constraints
- LunaRoute block runs on `request.RouteProvider` BEFORE the codex erasure in `ValidatePinRoutes` (otherwise codex+LunaRoute bypasses rule 7).
- Following mode + LunaRoute → `ErrLunaRoutePinnedOnly` refusal.
- Agent LunaRoute profile with empty `Profile.Backend` → `ErrLunaRouteBackendRequired` even when inventory filled a deployment-default backend into the request.
- Non-LunaRoute routes: behaviour unchanged (`caps` untouched).
- MCP text for LunaRoute refusals contains no connection name or credential (only model/backend/static guidance).

## Review Focus
- Existing tests that call `ValidatePinRoutes` / `NewModelSnapshotter` must be updated mechanically (extra trailing argument) — no behaviour change for them.
- `PinPreflight` keeps classifying LunaRoute refusals as refusals (they wrap `ErrInvalidSelection` / `ErrSpecificVersionUnavailable`).
- A LunaRoute agent profile that reaches the codex carve-out path (backend codex) is refused with the LunaRoute codex message, not passed as a subscription route.
- `profile_update` changing tools is a selection change and is revalidated; unchanged LunaRoute edits also recheck the pure policy without catalog I/O.

// ValidateSelection → inventory routes → ValidatePinRoutes' LunaRoute block,

func TestLunaRouteProfileSaveWiring(t *testing.T) {
	ds, call := lunaRouteMCP(t)
	isErr, text := call("connection_create", map[string]any{"name": "lr", "provider": "lunaroute", "base_url": "", "api_key": "lr_live_one"})

	assert.Contains(t, text, "LunaRoute on codex not yet supported")
	assert.Contains(t, text, `model "glm-5.3"`)

	isErr, text = call("profile_create", map[string]any{"alias": "lr-default", "kind": "agent", "connection_ref": "lr", "model": "glm-5.3"})
	assert.True(t, isErr)
	assert.Contains(t, text, "set backend to claude-code, opencode, codex or pi explicitly")

	isErr, text = call("profile_create", map[string]any{"alias": "lr-oc", "kind": "agent", "connection_ref": "lr", "model": "glm-5.3", "backend": "opencode"})
	assert.True(t, isErr)
	assert.Contains(t, text, "LunaRoute on opencode not yet supported")

	var n int
	require.NoError(t, ds.db.QueryRow("SELECT COUNT(*) FROM profiles WHERE alias LIKE 'lr-%'").Scan(&n))
