# LunaRoute Phase 2 · Task 7 — Refuse LunaRoute interactive agent streams; MCP authoring guidance for discovery and explicit selection

**Goal:** (a) An `interactive_agent` node on a LunaRoute agent profile fails closed in `InteractiveStreamSelector` (no LunaRoute interactive path exists) instead of reaching a subscription stream adapter — enforced at profile save through the root's inventory and at run time; (b) the MCP server instructions tell the authoring LLM to use `connection_models`, treat `unknown` as unknown, choose model and backend explicitly, and pair doer/judge by actual vendor.

**Architecture:** `adapter/provider/interactive_stream_selector.go:StreamProviderFor` checks `provider.IsLunaRoute(b.Provider)` for agent-kind bindings before backend dispatch and returns an error wrapping `ErrUnsupportedAgentBackend` that names LunaRoute. Chat-kind LunaRoute bindings keep flowing to `ChatProviderFor` (Task 4 arm). The selector is the one built in `cmd/arbitron/main.go` (`providersadapter.NewInteractiveStreamSelector`) and injected into both the interactive executor and `ExecutionPathInventory` (`Interactive:`), so the root test proves both. `adapter/mcp/authoring_guidance.go:AuthoringGuidance` gains a discovery/selection paragraph.

**Tech Stack:** Go 1.25, testify.

**Spec:** spec §Model discovery ("The LLM chooses a model and backend explicitly"; "Model-family safeguards reflect the actual model vendor"), non-goal "automatic model recommendations" · **Design:** phase-1 §3.7 (InteractiveStreamSelector), phase-2 §5 Deferred "Runtime policy", "Docs"

## Global Constraints
- The refusal happens before backend defaulting and before any stream factory is invoked.
- No fallback to claude subscription streaming, ever.
- Guidance must not recommend a model or say anything is auto-selected.

## Review Focus
- LunaRoute agent binding with an EMPTY backend (which would default to claude-code) is refused too.
- A LunaRoute chat-kind binding through the interactive selector still returns the chat provider.
- Saving a LunaRoute agent profile consumed by an `interactive_agent` node fails with the interactive refusal, not a later message.

`adapter/provider/interactive_stream_selector_lunaroute_test.go`:
```go
package provider_test

import (
	"testing"

	adapterprovider "github.com/arbitron/arbitron/adapter/provider"
	"github.com/arbitron/arbitron/domain/engine"
	"github.com/arbitron/arbitron/domain/provider"
	"github.com/stretchr/testify/assert"
	"github.com/stretchr/testify/require"
)

func TestInteractiveStreamSelector_RefusesLunaRouteAgent(t *testing.T) {
	built := 0
	_, _, streams := streamsByBackend()
	for k, f := range streams {
		inner := f
		streams[k] = func(b provider.ResolvedBinding) engine.ChatProvider {
			built++
			return inner(b)
		}
	}
	chatSentinel := &sentinelChatProvider{name: "chat"}
	sel := adapterprovider.NewInteractiveStreamSelector(&fakeChatProviderSelector{returns: chatSentinel}, streams, "claude-code")

	for _, backend := range []string{"claude-code", "codex", ""} {
		_, err := sel.StreamProviderFor(provider.ResolvedBinding{Kind: provider.ProfileKindAgent, Provider: "lunaroute", Backend: backend, Model: "glm-5.3"})
		require.ErrorIs(t, err, adapterprovider.ErrUnsupportedAgentBackend, "backend %q", backend)
		assert.Contains(t, err.Error(), "LunaRoute")
	}
	assert.Zero(t, built, "no stream adapter (subscription or otherwise) was constructed")

	got, err := sel.StreamProviderFor(provider.ResolvedBinding{Kind: provider.ProfileKindChat, Provider: "lunaroute", Model: "glm-5.3"})
	require.NoError(t, err)
	assert.Same(t, chatSentinel, got, "LunaRoute chat still streams through the chat selector")

	got, err = sel.StreamProviderFor(provider.ResolvedBinding{Kind: provider.ProfileKindAgent, Provider: "claude-cli", Backend: "claude-code"})
	require.NoError(t, err)
	assert.NotNil(t, got, "non-LunaRoute agents unchanged")
	assert.Equal(t, 1, built)
}
```

Run: `go test ./adapter/provider/ -run TestInteractiveStreamSelector_RefusesLunaRouteAgent -count=1`
Expected: FAIL — the claude-code LunaRoute binding returns the claude stream (`built` > 0).

```go
	case provider.ProfileKindAgent:
```

```go
package main

import (
	"os"
	"path/filepath"
	"testing"

	providersadapter "github.com/arbitron/arbitron/adapter/provider"
	"github.com/arbitron/arbitron/domain/provider"
	"github.com/stretchr/testify/assert"

// The root's InteractiveStreamSelector (shared by the interactive executor and
// the execution-path inventory) refuses a LunaRoute agent profile consumed by
// an interactive_agent node, so the save fails before any route is accepted.
func TestLunaRouteInteractiveAgentRefusedAtRoot(t *testing.T) {
	gw := newFakeLunaRouteGateway(t, "lr_live_int", "glm-5.3")
	ds := bootLunaRouteRoot(t, "", gw, func(ws string) {
		writeWorkflow(t, ws, "lr-int", `{"name":"lr-int","nodes":[
  {"id":"talk","type":"interactive_agent","entrypoint":true,
   "config":{"model_profile":"lr-int","orchestrationFile":"templates/o.md","templateFile":"templates/p.md"}}],"edges":[]}`)
		writePinTemplate(t, ws, "lr-int")
		require.NoError(t, os.WriteFile(filepath.Join(ws, "users", localDefaultUser.String(), "lr-int", "templates", "o.md"), []byte("orchestrate"), 0o600))
	})
	ctx := adminCtxForLocalUser(t, ds)
	require.NoError(t, ds.connSvc.Create(ctx, provider.Connection{Name: "lr", Provider: "lunaroute"}, "lr_live_int"))
	_, _, err := ds.profileSvc.Create(ctx, provider.Profile{Alias: "lr-int", Kind: provider.ProfileKindAgent, Backend: "claude-code", ConnectionRef: "lr", Model: "glm-5.3"})
	require.ErrorIs(t, err, providersadapter.ErrUnsupportedAgentBackend)
	assert.Contains(t, err.Error(), "LunaRoute agent profiles have no interactive streaming path")
	assert.Empty(t, gw.Requests())
}
```

- [ ] **Step 5: Extend the guidance**

In `adapter/mcp/authoring_guidance.go`, replace the final paragraph of `AuthoringGuidance`:
```
Profiles: model/provider selection is pinned per node via config.model_profile.
There is no convention for passing a profile as a workflow input.`
```
with:
```
Profiles: model/provider selection is pinned per node via config.model_profile.
There is no convention for passing a profile as a workflow input.

Model discovery: call connection_models with a connection name to see the
models it lists, each with its actual vendor family and capability facts (task
kinds, compatible backends, context/output limits, supported efforts). A field
marked "unknown" is not a guarantee, and a listed model is not thereby
compatible with every task or backend. Choose the model and, for agent
profiles, the backend (claude-code, codex, opencode or pi) explicitly;
LunaRoute profiles are pinned-only. Family is the actual vendor even behind a
gateway alias (claude-…-lr1 is anthropic): pair doer and judge across
different vendors, and do not select a model whose family is "unresolved".`
```
