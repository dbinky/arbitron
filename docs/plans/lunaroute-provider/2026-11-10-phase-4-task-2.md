# LunaRoute Phase 4 · Task 2 — codex LunaRoute mode (keyed, isolated, no subscription fallback)

**Dependencies:** P4-T1 codex verification (LR-07) and P3 complete.

**Shared contract:** Read [README.md](README.md) for execution order, production provenance and the five-category RED → GREEN → REFACTOR gate. All required coverage/provenance sections below belong to this task's RED/GREEN cycle and commit; read the complete document before Step 1.

**Goal:** When a codex binding's canonical provider is `lunaroute`, run `codex exec` against LunaRoute's Responses endpoint with the connection's guarded `lr_` key, a per-launch private `CODEX_HOME`, and `-c` model-provider overrides — never reading or writing `~/.codex` — while every non-LunaRoute codex launch stays byte-identical.

**Architecture:** New `adapter/codex/lunaroute.go` holds the mode: `lunaRouteExecExtra` (provider `-c` overrides from `provider.LunaRouteOpenAIBaseURL` + exact effort, no flooring) and `prepareLunaRouteLaunch` (guarded reveal → `procenv.CredentialEnv` with exactly one credential var `LUNAROUTE_API_KEY` → `os.MkdirTemp` 0700 private `CODEX_HOME` → cleanup closure). `Provider.RunAgent` branches on `provider.IsLunaRoute(p.binding.Provider)`; the private home is removed by `defer` on every exit path (success, error, timeout/cancel, panic) AFTER the pinned rollout check reads it. `ProbeExecutedModel` refuses LunaRoute (pinned-only, no account-model probe). The factory codex arm is unchanged (it already passes `Binding: b`); the Phase 2 wrapper decorates it. Enablement and routing changes are Task 3.

**Tech Stack:** Go 1.25, `os.MkdirTemp`, `adapter/procenv`, testify.

**Spec:** spec §Chat and agent workflows ("Agent work through Codex"), §Connection setup ("Credentials remain protected"), non-goal "changes to existing subscription-based connections" · **Design:** phase-4 §3.1, §7, §8

## Global Constraints
- Mode selection: `provider.IsLunaRoute(binding.Provider)` → LunaRoute mode; anything else → existing subscription mode, unchanged (including ignoring the provider and forwarding operator `CODEX_HOME`).
- LunaRoute env = `procenv.BaseEnv()` + `LUNAROUTE_API_KEY=<guarded key>` + `CODEX_HOME=<private temp dir>`; operator `CODEX_HOME`, `OPENAI_API_KEY` and `OPENAI_BASE_URL` are NOT forwarded (LR-07 decided).
- Argv contract (**LR-07 decided**, `docs/designs/2026-11-10-lunaroute-provider-decisions.md`): after `-m <model>`: `-c model_provider="lunaroute"`, `-c model_providers.lunaroute.name="LunaRoute"`, `-c model_providers.lunaroute.base_url="https://gw.lunaroute.com/v1"`, `-c model_providers.lunaroute.env_key="LUNAROUTE_API_KEY"` (codex sends it as Bearer, LR-01), `-c model_providers.lunaroute.wire_api="responses"`, `-c review_model="<model>"` (the helper selector, pinned to the binding model), then optional `-c model_reasoning_effort=<low|medium|high|xhigh>`. Compaction uses the main model.
- Effort: default → nothing; low/medium/high/xhigh verbatim; none/max → `LunaRouteRefusal{Reason: ErrLunaRouteAxisUnsupported}` before any launch (never "minimal", never floored).
- Order: build argv (no secret) → guarded reveal → create private home → version probe → launch. A reveal/endpoint/effort failure launches nothing and creates no temp dir.
- Key appears only in the child env: never argv, never errors/logs.
- **LR-07 decided:** the literals above are the contract (verified-on codex-cli 0.167.0). Phase 4 Task 1 verifies them. An override the binary ignores is removed here in one edit; a login requirement or off-connection traffic stops P4-T3 enablement (On-failure rule).

## Review Focus
- Operator `CODEX_HOME=/somewhere` set in the server env must NOT reach a LunaRoute launch (it would point codex at the user's subscription auth).
- Pinned LunaRoute runs: the rollout verifier must read the PRIVATE home before it is removed (a cleanup-before-verify bug would make every pinned run fail).
- `effort: max` on codex: refused, not silently dropped.
- Context cancellation mid-run removes the temp dir.
- Two concurrent LunaRoute launches get distinct homes.

// LunaRouteKeyVar is the single credential variable a LunaRoute codex launch
// carries; codex reads it through model_providers.lunaroute.env_key.
// LR-07 (decided 2026-11-10, docs/designs/2026-11-10-lunaroute-provider-decisions.md):
// the -c keys below are the contract, verified by
// test/lunaroute/backends_live_test.go:TestLiveCodexLunaRoute.
const LunaRouteKeyVar = "LUNAROUTE_API_KEY"

const (
	lunaRouteProviderID = "lunaroute"
	lunaRouteWireAPI    = "responses"
	lunaRouteHomePrefix = "arbitron-codex-lunaroute-"
)

// lunaRouteExecExtra returns the -c overrides that define and select the
// LunaRoute model provider, plus the exact effort override. It carries no
// secret: the credential is referenced by env var NAME only.
func lunaRouteExecExtra(b provider.ResolvedBinding) ([]string, error) {
	base, err := provider.LunaRouteOpenAIBaseURL(b.BaseURL)
	if err != nil {
		return nil, err
	}
	extra := []string{
		"-c", `model_provider="` + lunaRouteProviderID + `"`,
		"-c", `model_providers.lunaroute.name="LunaRoute"`,
		"-c", `model_providers.lunaroute.base_url="` + base + `"`,
		"-c", `model_providers.lunaroute.env_key="` + LunaRouteKeyVar + `"`,
		"-c", `model_providers.lunaroute.wire_api="` + lunaRouteWireAPI + `"`,
		// LR-07 decided: the review helper uses the binding model.
		"-c", `review_model="` + strings.TrimSpace(b.Model) + `"`,
	}
	effort, err := lunaRouteEffortArgs(b)
	if err != nil {
		return nil, err
	}
	return append(extra, effort...), nil
}

// lunaRouteEffortArgs emits only efforts codex sends verbatim. LunaRoute never
// uses the capability-rule flooring: none (→ "minimal") and max are refused.
func lunaRouteEffortArgs(b provider.ResolvedBinding) ([]string, error) {
	switch b.Effort {
	case "", provider.EffortDefault:
		return nil, nil
	case provider.EffortLow, provider.EffortMedium, provider.EffortHigh, provider.EffortXHigh:
		return []string{"-c", codexEffortConfigKey + "=" + string(b.Effort)}, nil
	case provider.EffortNone, provider.EffortMax:
		return nil, &provider.LunaRouteRefusal{Reason: provider.ErrLunaRouteAxisUnsupported, Model: b.Model, Backend: workflow.BackendCodex,
			Detail: fmt.Sprintf("effort %q has no exact codex emission; set effort to default, low, medium, high or xhigh", b.Effort)}
	default:
		return nil, fmt.Errorf("%w: %q", provider.ErrInvalidEffort, string(b.Effort))
	}
}

// lunaRouteLaunch is one prepared LunaRoute codex launch. cleanup removes the
// private CODEX_HOME and must run on every exit path.
type lunaRouteLaunch struct {
	env     []string
	home    string
	cleanup func()
}

// prepareLunaRouteLaunch reveals the key through the LunaRoute guard (hosted
// endpoint + lr_ shape) BEFORE creating anything, then creates an owner-only
// private CODEX_HOME so codex never reads or writes the user's ~/.codex
// (auth.json, config.toml, sessions). Operator CODEX_HOME and any ambient
// OPENAI_API_KEY are not forwarded.
func prepareLunaRouteLaunch(ctx context.Context, b provider.ResolvedBinding) (lunaRouteLaunch, error) {
	guarded := provider.GuardLunaRouteReveal(b)
	env, err := procenv.CredentialEnv(ctx, procenv.CredentialSpec{
		Runner:   "codex: lunaroute",
		KeyVar:   LunaRouteKeyVar,
		Reveal:   guarded.RevealKey,
		EmptyKey: procenv.EmptyKeyReject,
	})
	if err != nil {
		return lunaRouteLaunch{}, err
	}
	home, err := os.MkdirTemp("", lunaRouteHomePrefix)
	if err != nil {
		return lunaRouteLaunch{}, fmt.Errorf("codex: lunaroute: create private CODEX_HOME: %w", err)
	}
	if err := os.Chmod(home, 0o700); err != nil {
		_ = os.RemoveAll(home)
		return lunaRouteLaunch{}, fmt.Errorf("codex: lunaroute: secure private CODEX_HOME: %w", err)
	}
	env = procenv.RemoveVar(env, codexHomeVar)
	env = procenv.RemoveVar(env, "OPENAI_API_KEY")
	env = procenv.RemoveVar(env, "OPENAI_BASE_URL")
	env = append(env, codexHomeVar+"="+home)
	return lunaRouteLaunch{env: env, home: home, cleanup: func() { _ = os.RemoveAll(home) }}, nil
}
