## Global Constraints

- Examples use model ids that pass the Phase-1 grammar (`glm-5.3`, `glm-5.3-flash`, `deepseek-4.1-flash`).
- State plainly: codex and pi are not yet enabled (Phase 4 updates this); no fallbacks, no recommendations; LunaRoute profiles are pinned-only and must name their backend.
- No real keys: `lr_…` placeholder only.

## Review Focus

- A doc example with `GLM-5.3` or `latest` must fail the doc test.
- Lines that are not `connection`/`profile` inside the block are ignored, but a block with zero profiles fails (the parser cannot silently find nothing).

package lunaroute_test

import (
	"context"
	"errors"
	"os"
	"path/filepath"
	"strings"
	"testing"

	"github.com/arbitron/arbitron/domain/modelidentity"
	"github.com/arbitron/arbitron/domain/provider"
	"github.com/stretchr/testify/assert"
	"github.com/stretchr/testify/require"
)

type docProfile struct{ Alias, Kind, Backend, Model string }

func parseLunaRouteDocExamples(doc string) ([]docProfile, error) {
	start := strings.Index(doc, "```text\n")
	if start < 0 {
		return nil, errors.New("no ```text example block")
	}
	rest := doc[start+len("```text\n"):]
	end := strings.Index(rest, "```")
	if end < 0 {
		return nil, errors.New("unterminated example block")
	}
	var out []docProfile
	for _, line := range strings.Split(rest[:end], "\n") {
		fields := strings.Fields(line)
		if len(fields) < 2 || fields[0] != "profile" {
			continue
		}
		p := docProfile{Alias: fields[1]}
		for _, f := range fields[2:] {
			k, v, _ := strings.Cut(f, "=")
			switch k {
			case "kind":
				p.Kind = v
			case "backend":
				p.Backend = v
			case "model":
				p.Model = v
			}
		}
		out = append(out, p)
	}
	if len(out) == 0 {
		return nil, errors.New("example block has no profile lines")
	}
	return out, nil
}

func TestParseLunaRouteDocExamples(t *testing.T) {
	got, err := parseLunaRouteDocExamples("x\n```text\nconnection c provider=lunaroute\nprofile a kind=agent backend=opencode connection=c model=glm-5.3\n```\n")
	require.NoError(t, err)
	assert.Equal(t, []docProfile{{Alias: "a", Kind: "agent", Backend: "opencode", Model: "glm-5.3"}}, got)
	_, err = parseLunaRouteDocExamples("```text\nconnection only\n```")
	require.Error(t, err)
	_, err = parseLunaRouteDocExamples("no block")
	require.Error(t, err)
}

// Every documented LunaRoute profile is a selection the product accepts on
// grammar, vendor family and backend enablement.
func TestLunaRouteGuideExamplesAreValid(t *testing.T) {
	raw, err := os.ReadFile(filepath.Join(repoRoot(t), "docs", "setup", "lunaroute.md"))
	require.NoError(t, err)
	profiles, err := parseLunaRouteDocExamples(string(raw))
	require.NoError(t, err)
	kinds := map[string]bool{}
	for _, p := range profiles {
		kinds[p.Kind] = true
		_, err := modelidentity.NewVersionResolver().SpecificVersion(context.Background(),
			modelidentity.VersionRequest{Model: p.Model, RouteProvider: "lunaroute", ConnectionRef: "doc", Backend: p.Backend})
		assert.NoError(t, err, "%s: model %q", p.Alias, p.Model)
		assert.NotEqual(t, modelidentity.FamilyUnresolved, modelidentity.ClassifyFamily("lunaroute", p.Model), p.Alias)
		switch p.Kind {
		case "agent":
			assert.True(t, provider.LunaRouteBackendEnabled(p.Backend), "%s: backend %q is not enabled for LunaRoute", p.Alias, p.Backend)
		case "chat":
			assert.Empty(t, p.Backend, "%s: chat profiles name no backend", p.Alias)
		default:
			t.Errorf("%s: unknown kind %q", p.Alias, p.Kind)
		}
	}
	assert.True(t, kinds["chat"] && kinds["agent"], "the guide shows both a chat and an agent profile")
}
```

`docs/setup/lunaroute.md`:
````markdown
# LunaRoute provider

LunaRoute is a hosted gateway serving open-weight and proprietary models. In
Arbitron it is an ordinary connection + profiles: no new node types, no
LunaRoute CLI, plugin or login. Every LunaRoute call goes to the hosted
endpoint `https://gw.lunaroute.com` with the connection's `lr_` key.

## 1. Create the connection (MCP `connection_create`, admin)

```json
{"name": "lunaroute-main", "provider": "lunaroute", "base_url": "", "api_key": "lr_…"}
```

- The key must start with `lr_`. Keys from other providers are rejected, never
  forwarded (LunaRoute would treat them as bring-your-own upstream keys).
- `base_url` may be empty, `https://gw.lunaroute.com` or `…/v1`; it is stored as
  the root. Any other destination is rejected.
- Switching an existing connection to `lunaroute` requires a new `api_key`.

## 2. Inspect models (MCP `connection_models`)

`connection_models {"name": "lunaroute-main"}` lists the ids the connection can
reach now, with family, task kinds, backends, context/output limits and effort
support. A field marked `unknown` is not a guarantee either way; being listed
does not mean a model works for a task or backend. You choose the model and the
backend explicitly — nothing is recommended or substituted.

## 3. Create profiles (MCP `profile_create`, admin)

```text
connection  lunaroute-main   provider=lunaroute  base_url=https://gw.lunaroute.com  api_key=lr_…
profile     chat-glm53-flash kind=chat                          connection=lunaroute-main  model=glm-5.3-flash
profile     coder-glm53-oc   kind=agent  backend=opencode       connection=lunaroute-main  model=glm-5.3
profile     coder-glm53-cc   kind=agent  backend=claude-code    connection=lunaroute-main  model=glm-5.3
profile     coder-ds41-oc    kind=agent  backend=opencode       connection=lunaroute-main  model=deepseek-4.1-flash
```

Rules enforced at save and again before every launch:

- LunaRoute profiles are **pinned** (`selection_mode` following is refused) and
  agent profiles must **name their backend**; deployment defaults never pick one.
- Models must be LunaRoute catalog spellings: `glm-N[.N][-flash][-background]`,
  `deepseek-N[.N]-{flash,pro}[-background]`, `claude-{tier}-N[-N]-lrN[-background]`.
  `-background` is used only when you name it.
- The model's vendor must be known (`claude-…-lrN` aliases count as Anthropic for
  doer/judge separation); unresolved families are refused.
- `context_window` must be `default` (Claude `200k`/`1m` tiers are not LunaRoute
  limits). A non-default `effort` needs recorded support for that model and an
  exact emission path (opencode has none).
- **claude-code needs known context and output limits** for the model in the
  capability table (below); otherwise the profile is refused.
- Backends enabled in this release: `claude-code`, `opencode`. `codex` and `pi`
  are refused with "not yet supported".

## 4. Capability facts (operator)

Known per-model facts live in the capabilities override file
(`capabilitiespath`, default `~/.arbitron/capabilities.yaml`). Every fact needs
evidence recorded under `docs/evidence/lunaroute-provider/`:

```yaml
lunaroute_models:
  glm-5.3:
    context_tokens: {tokens: <from evidence>, evidence: "docs/evidence/lunaroute-provider/<file>#<anchor>"}
    output_tokens:  {tokens: <from evidence>, evidence: "docs/evidence/lunaroute-provider/<file>#<anchor>"}
    backends:
      opencode: {support: supported, evidence: "…"}
```

Omitted facts are `unknown`. No LunaRoute facts ship by default.

## 5. What errors mean

| Message starts with | Meaning / what to do |
|---|---|
| `LunaRoute rejected the credential` | Update the connection with a valid `lr_` key. |
| `the selected model is not available` | Run `connection_models`; pick a listed id. |
| `LunaRoute is busy` | All lanes in use; retry later. |
| `LunaRoute service failure` | Gateway/transport failure; retry later. |
| `LunaRoute request failed and the cause is unknown` | Arbitron could not tell why; the message includes a redacted snippet and, for agent runs, a later observation that does not prove the original cause. |
| `… not yet supported` / `… needs known context and output limits` / `… not a verified fixed catalog spelling` | Selection refused before any call; change the named setting. |

Nothing falls back to another model, backend or provider.
