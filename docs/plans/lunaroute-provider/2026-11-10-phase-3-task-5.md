# LunaRoute Phase 3 · Task 5 — Evidence first, then real Claude Code/OpenCode tool-task verification

**Dependencies:** Preparation uses P1-T11 framework, P2-T8/P2-T9 and installed harnesses, independent of P3 adapters. Final adapter verification follows P3-T3; the guide in P3-T4 is independent of that final experiment. Read [README.md](README.md).

**Goal:** Verify the decided LR-05/LR-06 contracts (`docs/designs/2026-11-10-lunaroute-provider-decisions.md`) against the installed binaries, apply each decision's On-failure rule, then complete tool work through the production adapters and record all main/supporting routing evidence.

**Spec:** `docs/specs/2026-11-10-lunaroute-provider-spec.md`; design phase 3 §§3,5,8.

## Global constraints

- LR-05/LR-06 are **decided** contracts (Claude Code: Bearer via `ANTHROPIC_AUTH_TOKEN`, six selectors, hints, limits, `--setting-sources ""`; OpenCode: restricted overlay with `model`/`small_model`/`enabled_providers`, registered `limit`/`tool_call`, `--pure`). The register stays `decided` until recorded evidence proves the installed version's controls, precedence and helper routing; then it becomes `verified`. Emitting a key the binary ignores is a defect: remove it (On-failure rule). An unroutable helper stops that backend's enablement and sets the item to `escalated`.
- No shared `~/.claude`/OpenCode auth/config writes. Record versions and credential-free config/request evidence. Isolate candidate experiments from ambient credentials and use only the selected LunaRoute connection/model.
- Limits/efforts/settings come from LR-02 source notes; vendor/fixed-id/response spelling from LR-03. A completed short task establishes none of the maxima.
- Missing key/binary/required facts skips local experiments with a readiness-pending message. Release mode (`ARBITRON_LUNAROUTE_RELEASE_GATE=1`) fails missing prerequisites; no empty observation is success.
