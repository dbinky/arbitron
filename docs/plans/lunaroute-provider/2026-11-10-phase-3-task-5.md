# LunaRoute Phase 3 · Task 5 — Evidence first, then real Claude Code/OpenCode tool-task verification

**Dependencies:** Preparation uses P1-T11/P2-T8 and installed harnesses, independent of P3 adapters. Final adapter verification follows P3-T1–T4. Read [README.md](README.md).

**Goal:** Settle LR-05/LR-06 before final env/config choices; then complete tool work through the production adapters and record all main/supporting routing evidence.

**Spec:** `docs/specs/2026-11-10-lunaroute-provider-spec.md`; design phase 3 §§3,5,8.

## Global constraints

- LR-05/LR-06 remain **UNRESOLVED DEPENDENCIES** until recorded evidence proves the actual installed version's controls, precedence, required metadata, and helper routing. Emitting a key that is ignored is a defect, not harmless partial support.
- No shared `~/.claude`/OpenCode auth/config writes. Record versions and credential-free config/request evidence. Isolate candidate experiments from ambient credentials and use only the selected LunaRoute connection/model.
- Limits/efforts/settings come from LR-02 source notes; vendor/fixed-id/response spelling from LR-03. A completed short task establishes none of the maxima.
- Missing key/binary/required facts skips local experiments with a readiness-pending message. Release mode (`ARBITRON_LUNAROUTE_RELEASE_GATE=1`) fails missing prerequisites; no empty observation is success.

### Task 5: Two evidence milestones, one owner

**Files:**

- Create: `test/lunaroute/agent_live_test.go`
- Extend: `docs/evidence/lunaroute-provider/README.md`, `register.yaml`
- Produce: `observations/lr05-contract.md`, `lr06-contract.md`, `lr05-claude-code-agent.json`, `lr06-opencode-agent.json` and supporting-call notes.

**Interfaces:** Test package `lunaroute_test`, shared with P4-T1.

- `liveBinary(t *testing.T, name string) string`: executable path or explicit local skip/release failure.
- `liveModel(envVar string) string`: requires the named, explicitly selected reviewed model; no recommendation/default model.
- `versionOf(t *testing.T, bin string) string`: bounded version query; safe text only.
- `liveRules(t *testing.T) provider.CapabilityRules`: loads `ARBITRON_LUNAROUTE_E2E_CAPABILITIES` through the real loader.
- `liveBinding(key, model, backend string) provider.ResolvedBinding`: Kind agent, LunaRoute root, `BackendExplicit:true`, `Pinned:true`, guarded RevealKey and explicit tools.
- `liveFactory(ws, claudeBin string, rules provider.CapabilityRules) *providersadapter.Factory`: real runner, ClaudeAgentConfig including same rules/workspace, shared Factory rules and probe factory.
- `runLiveMission(t *testing.T, f *providersadapter.Factory, b provider.ResolvedBinding, ws string) (*engine.AgentResult,string)`: fresh empty workdir, bounded context, production RunAgent; verifies exact created file, command-generated result and tool_call steps before returning.
- Consume P1-T11 `liveKey`, `writeObservation`, `repoRoot`; do not redefine these helpers in later tasks.

- [ ] **Step 1: Prepare the runtime contracts before P3-T1/T2**

Query installed versions/help and authoritative harness/LunaRoute documentation. Run direct isolated experiments (not the not-yet-implemented adapters) and record:

1. Claude Code: accepted auth header; all main, Haiku/small-fast, subagent/title/summary/compaction selectors; effective context/output limit controls; exact effort values; ambient user/workspace configuration precedence.
2. OpenCode: provider/SDK id, `/v1` base, env-referenced key, executable model argv, required custom model metadata, small/helper model selection and provider restrictions. Determine whether limits/reasoning metadata require new fields/feed from P1-T8; if required, add those explicit fields and factory/root sink tests to P3-T2 **before** enabling it.
3. Provoke at least one supporting call per reachable helper category (compaction needs a suitable test context). Capture credential-free request evidence identifying destination, selected connection handle and model, plus effective configuration. Absence of helper requests is not proof they are routed correctly.
4. Seed conflicting user and project config selecting another provider/model and credentials. Verify precedence and no shared-file writes by comparing file bytes before/after. If controls cannot enforce the spec, preserve LR-05/LR-06 and stop dependent enablement; do not publish candidate env/config as verified.

- [ ] **Step 2: Implement test/evidence tooling with strict TDD**

Write RED fixture tests for the observation validator before implementation: happy completed tool task accepted; success requires both main and helper evidence; failure missing tool_call/file/command result rejected; error malformed config/request records and secret-bearing observations refused; edge zero helper requests, wrong model/provider, missing evidence references and skipped prerequisites rejected. Use P1-T11's observation writer, which redacts/rejects secrets before output.

Run `go test ./test/lunaroute -run 'AgentEvidence|Observation' -count=1` RED, implement bounded helpers/validator, run GREEN and refactor. Never print raw stderr, debug config or an unsanitized `exec.ExitError`.

- [ ] **Step 3: Verify production adapters after P3-T3**

Implement `TestLiveClaudeCodeAgentTask` and `TestLiveOpencodeAgentTask`. Env choices are `ARBITRON_LUNAROUTE_E2E_CLAUDE_MODEL` and `_OPENCODE_MODEL`; validate both appear in the selected connection listing. The task creates `lunaroute-proof.txt` containing exact `LUNAROUTE-OK`, runs a shell command to produce a second result file, reads/asserts both and requires `res.Steps` to contain `tool_call`. A summary echo or a manually precreated file cannot pass.

Run through real Factory/runner with pinned binding and the same table the root uses. Require successful terminal turn and executed-model evidence, then record model/version, result booleans, tool step kinds and references to the independently collected supporting-call evidence. Debug effective config must be collected from the **same emitted env/config/cwd used by that run**, never a reconstructed config under `os.Environ()`. Use a capturing real-runner decorator if needed, persisting only safe selectors/limits and field names, never credentials or arbitrary output.
