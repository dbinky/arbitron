# LunaRoute Phase 4 · Task 1 — Verify codex and pi runtime contracts before implementation

**Dependencies:** P1-T11 evidence preparation, LR-01–LR-03 facts and P3-T5 shared helper definitions. Independent of P4 production adapters. Read [README.md](README.md).

**Goal:** Verify the decided LR-07/LR-08 contracts (`docs/designs/2026-11-10-lunaroute-provider-decisions.md`) using the installed binaries (verified-on codex-cli 0.167.0, pi 1.5.1), the required model metadata and main/helper requests, and apply each decision's On-failure rule.

**Spec:** `docs/specs/2026-11-10-lunaroute-provider-spec.md`; design phase 4 §§3,5,8.

## Global constraints

- **LR-07 decided:** private 0700 `CODEX_HOME` (no `auth.json`/`config.toml`), env `LUNAROUTE_API_KEY` only (operator `CODEX_HOME`, `OPENAI_API_KEY`, `OPENAI_BASE_URL` not forwarded), `-c model_provider="lunaroute"`, `-c model_providers.lunaroute.{name="LunaRoute", base_url="<root>/v1", env_key="LUNAROUTE_API_KEY", wire_api="responses"}`, `-c review_model="<id>"`. Codex sends the key as Bearer.
- **LR-08 decided:** relocation is supported (`PI_CODING_AGENT_DIR`, pi 1.5.1 `docs/configuration.md`), and an untrusted private dir does not load project `.pi` config. `models.json.providers.lunaroute = {baseUrl:"<root>/v1", api:"openai-completions", apiKey:"$LUNAROUTE_API_KEY", authHeader:true, models:[{id, name, reasoning, input:["text"], contextWindow, maxTokens}]}` with reasoning/limits from LR-02 (unknown → refuse; pi's defaults are never relied on); `--model lunaroute/<id>`. The earlier candidate `apiKey:"LUNAROUTE_API_KEY"` was a defect (pi treats it as a literal key).
- **On failure** (decisions doc): an ignored codex override is dropped. A codex login requirement, or any request leaving the connection or model, stops P4-T3 enablement and sets LR-07 to `escalated`. If pi relocation or the schema misbehaves, pi + LunaRoute stays refused and LR-08 becomes `escalated`. Never modify shared `~/.pi`/`~/.codex`, and never remove Pi from scope.
- Credentials remain only in child env. No raw stderr/help/config values are printed or written; redact before truncation. Bound process contexts, stdout, stderr and cleanup.

- [ ] **Step 3: Complete representative tool tasks**

Each binary must create `lunaroute-ok.txt` containing exact `ok`, execute a command generating `listing.txt`, leave successful terminal evidence and prove the selected model/provider. Require nonempty parsed model records, scanner.Err()==nil, correlation to the run/thread and a successful **final** terminal event. Verify private config directories during execution and cleanup afterwards, no shared writes, no subscription credential use, and conflicting workspace defaults cannot win. Record exact versions alongside the verified contract. There is no runtime version gate (as for LR-05/LR-06); a binary upgrade requires re-running this task before the next release.
