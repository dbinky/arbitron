- **LR-07 decided:** private 0700 `CODEX_HOME` (no `auth.json`/`config.toml`), env `LUNAROUTE_API_KEY` only (operator `CODEX_HOME`, `OPENAI_API_KEY`, `OPENAI_BASE_URL` not forwarded), `-c model_provider="lunaroute"`, `-c model_providers.lunaroute.{name="LunaRoute", base_url="<root>/v1", env_key="LUNAROUTE_API_KEY", wire_api="responses"}`, `-c review_model="<id>"`. - **LR-08 decided:** relocation is supported (`PI_CODING_AGENT_DIR`, pi 1.5.1 `docs/configuration.md`), and an untrusted private dir does not load project `.pi` config. `models.json.providers.lunaroute = {baseUrl:"<root>/v1", api:"openai-completions", apiKey:"$LUNAROUTE_API_KEY", authHeader:true, models:[{id, name, reasoning, input:["text"], contextWindow, maxTokens}]}` with reasoning/limits from LR-02 (unknown → refuse; pi's defaults are never relied on); `--model lunaroute/<id>`. - **On failure** (decisions doc): an ignored codex override is dropped. A codex login requirement, or any request leaving the connection or model, stops P4-T3 enablement and sets LR-07 to `escalated`. If pi relocation or the schema misbehaves, pi + LunaRoute stays refused and LR-08 becomes `escalated`. Never modify shared `~/.pi`/`~/.codex`, and never remove Pi from scope.
- Credentials remain only in child env. No raw stderr/help/config values are printed or written; redact before truncation. Bound process contexts, stdout, stderr and cleanup.
