# LunaRoute Phase 3 · Task 2 — opencode LunaRoute descriptor, config, argv and env

**Dependencies:** P2 complete; P3-T5 evidence-only preparation (LR-06) precedes final config implementation.

**Shared contract:** Read [README.md](README.md) for execution order, production provenance and the five-category RED → GREEN → REFACTOR gate. All required coverage/provenance sections below belong to this task's RED/GREEN cycle and commit; read the complete document before Step 1.

**Goal:** A `lunaroute` binding on the opencode backend launches `opencode run -m lunaroute/<id>` with a static `@ai-sdk/openai-compatible` provider block whose `baseURL` is the hosted root **plus `/v1`**, whose `apiKey` references `{env:LUNAROUTE_API_KEY}`, which registers the selected model explicitly and points opencode's small (supporting) model at the same model — with the guarded `lr_` key only in the child env, non-default effort refused, and harness stderr never copied into errors/logs.

**Architecture:** One new row in `adapter/opencode/providers.go:providerDescriptors` (`provider.CanonicalLunaRoute`). `adapter/opencode/config.go:buildConfig` gains a LunaRoute branch: base URL derived with `provider.LunaRouteOpenAIBaseURL` (the current builder copies `binding.BaseURL` verbatim, which would emit the root without `/v1`), `providerBlock.Models` registration and top-level `small_model` (new `omitempty` fields → non-LunaRoute JSON byte-identical). `adapter/opencode/env.go:opencodeEnv` re-applies `provider.GuardLunaRouteReveal`. `adapter/opencode/provider.go:RunAgent` refuses non-default effort for LunaRoute (opencode has no effort emission) before any reveal, and sanitizes process errors for LunaRoute like pinned runs. No plugin, no `/connect`, no on-disk auth store.

**Tech Stack:** Go 1.25, testify.

**Spec:** spec §Chat and agent workflows ("Agent work through OpenCode"; supporting calls stay on the selected connection/model) · **Design:** phase-3 §3.2, §4, §7, §8

- Config: `provider.lunaroute = {npm: "@ai-sdk/openai-compatible", options: {apiKey: "{env:LUNAROUTE_API_KEY}", baseURL: "https://gw.lunaroute.com/v1"}, models: {"<id>": {}}}` and `small_model: "lunaroute/<id>"`.

- Effort: any non-default effort → `LunaRouteRefusal{ErrLunaRouteAxisUnsupported}` before reveal (the domain rule already refuses at save/launch; this is the backend's own fail-closed check).
- Non-LunaRoute rows, config JSON, argv and env unchanged (golden tests).
- **UNRESOLVED DEPENDENCY LR-06 / ESCALATION LR-06:** whether the installed opencode version (a) requires explicit custom-model registration under `provider.<id>.models`, (b) honours top-level `small_model` for title/summary/compaction calls, (c) accepts `-m lunaroute/<id>`, and (d) can be stopped from auto-loading other configured providers (`enabled_providers`/`disabled_providers`) is unverified. Phase 3 Task 5 preparation MUST settle (a)–(d) before this emitter is finalized or enabled. Implement the verified model/helper/provider restriction fields and required metadata here; an ignored key is a failed contract, never harmless accepted behavior.
- **UNRESOLVED DEPENDENCY LR-01:** the `/v1` OpenAI-dialect path; the helper is the single place to change it.
