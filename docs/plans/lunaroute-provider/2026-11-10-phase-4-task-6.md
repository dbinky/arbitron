import (

		}

`adapter/mcp/lunaroute_backend_hint.go`:
```go
package mcp

// LunaRouteBackendHint is appended to the profile_create / profile_update tool
// descriptions: the facts an author needs when pointing a profile at a
// LunaRoute connection. It never recommends a model.
const LunaRouteBackendHint = " LunaRoute: list a connection's models and their known/unknown capabilities with connection_models, then choose the model and backend explicitly; LunaRoute selections are pinned only, and an agent profile must name its backend explicitly (claude-code, opencode, codex or pi)." +
	" codex on LunaRoute runs keyed against the gateway with a private CODEX_HOME per run (never ~/.codex); the codex backend-health login verdict is informational for these runs and does not gate them." +
	" pi on LunaRoute writes a per-run private provider definition and, like claude-code, needs known context and output limits for the model in the capability table; unknown limits are refused rather than guessed."
```

In `adapter/mcp/tools_profile.go`, append `+LunaRouteBackendHint` to the `gomcp.WithDescription(...)` string of `profile_create` and of `profile_update`, e.g.:
```go
			gomcp.WithDescription("Create a model profile (admin only). Validates context_window/effort against the backend/model capability rules and echoes the floored effective values. The response carries both profile.* (your requested axes, as stored) and effective.* (the values that will actually take effect at launch); compare them to detect whether a requested axis was floored to the backend/model ceiling."+LunaRouteBackendHint),
```
(same `+LunaRouteBackendHint` suffix on the `profile_update` description; if Phase 2 already appended its own LunaRoute hint there, append this one after it.)

## codex and pi

Both backends run LunaRoute keyed against `https://gw.lunaroute.com/v1` and
never touch your personal harness config:

- **codex** gets `LUNAROUTE_API_KEY` and a private, per-run `CODEX_HOME`

  `-c model_providers.lunaroute.{name,base_url,env_key,wire_api}` overrides.
  `~/.codex/auth.json` is never read. The codex backend-health login verdict
  (dashboard / `system_config`) describes the ChatGPT subscription only; it does
  not gate LunaRoute codex runs.
- **pi** gets `LUNAROUTE_API_KEY` and a private, per-run `PI_CODING_AGENT_DIR`
  containing a `models.json` custom provider (`lunaroute`). The model's context
  and output limits must be recorded in `lunaroute_models` (capabilities file)
  with evidence; otherwise the profile is refused.

Example profiles (choose ids listed by `connection_models`; facts must be in
`lunaroute_models` where required):

| alias | kind | backend | connection | model | effort |

| coder-glm-codex | agent | codex | lunaroute-main | glm-5.3 | default |

`effort` on codex: only `low|medium|high|xhigh` (no `none`/`max`), and only
when the table records support for the model on codex. On pi: `none` through
`max` when recorded.

Contract status: the codex `-c` keys (including `review_model`, with a private
`CODEX_HOME`) and the pi `models.json` / `PI_CODING_AGENT_DIR` contract are
decided (LR-07 / LR-08 in

`docs/evidence/lunaroute-provider/register.yaml`; they are not release-ready
