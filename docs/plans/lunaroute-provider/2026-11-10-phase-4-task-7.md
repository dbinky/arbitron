# LunaRoute Phase 4 · Task 7 — Completed MCP release matrix and evidence gate

**Dependencies:** P4-T6, all four enabled/fed adapters, and the LR-01–LR-08 decided contracts (`docs/designs/2026-11-10-lunaroute-provider-decisions.md`) applied to production sources, with their verification artifacts. Read [README.md](README.md).

**Goal:** An LLM's real MCP connection/discovery/profile/workflow path completes chat, a reviewed proprietary/alias selection and tool work on every required backend, with truthful capability/error/safeguard evidence.

**Spec:** `docs/specs/2026-11-10-lunaroute-provider-spec.md` (all Outcomes); design phase 4 §9.

## Global constraints

- Successful process launch, saved profile, model pin, empty evidence or skipped test is insufficient.
- No substitution: assert **execution evidence** as well as requested pins, backend, provider/connection destination and completed workspace output.
- Matrix models come from the decided release set: open-weight `glm-5.3` (agent) and `glm-5.3-flash` or `deepseek-4.1-flash-1017` (chat). The reviewed proprietary alias `claude-sonnet-5-lr1` must complete one task. Its execution evidence must report an `anthropic`-family model (the LR-03 alias exception), and the matrix records any drift. A same-vendor doer/judge pairing that includes the alias must be rejected.
- Families are actual vendors. Equality of two classifier results alone does not demonstrate safeguard rejection. Existing sample safeguard owns pairing rejection; no runtime doer/judge role field is invented.
- Missing live prerequisites may skip local opt-in tests with explicit readiness-pending text. With `ARBITRON_LUNAROUTE_RELEASE_GATE=1`, missing key/models/binaries/table/observations is a failure, never SKIP. Readiness requires current completed artifacts, not merely verified labels in YAML.
- Every LR item that is not `verified` (that is, still `decided` or `escalated`) blocks readiness until its verification evidence exists. This task does not convert decided contracts or operator instructions into verified facts.

- [ ] **Step 1: RED tests for acceptance/evidence tooling**

Happy fixture has chat output and four successful terminal tool tasks. Success requires actual file, command/tool evidence, selected executable identity and main/helper source references. Failure fixtures include missing backend, alias profile only saved but never executed, failed Pi turn with exit 0, wrong output and substitution. Error fixtures reject missing/unreadable log/evidence files, invalid JSON, unbounded/failed polling and secrets. Edge fixtures reject empty model lists, no helper requests, skipped prerequisite flags and stale/mismatched binary/model/source references. Implement parsers/validator only after observing these failures; run `go test ./cmd/arbitron -run 'LunaRouteAcceptanceEvidence' -count=1` RED/GREEN and refactor.

- [ ] **Step 2: Boot and drive the real MCP server**

Drive MCP `connection_create` → `connection_models` → `profile_create` → `instance_trigger` → `instance_get` polling to completion. Check no tool error, nonempty discovered ids, explicit known/unknown fields and evidence references, correct actual family and no credential output. Reject a foreign key through the real write seam. - [ ] **Step 4: Error/refusal matrix without fabricated production ids**

- Invalid `lr_` credential: discovery and a chat run return credentials-rejected text through MCP, with no disclosure.
- Unavailable model: `_E2E_UNAVAILABLE_MODEL` must be a reviewed fixed executable id absent from this connection's authoritative successful listing; save may succeed, inference fails with model-unavailable when the verified protocol establishes it. Unknown cause remains explicit only when genuinely not known. Do not invent `glm-999.9` and require an unreviewed id to save past P1-T7. If no live unavailable id is accessible, use P2 root fixtures and record that negative test's scope explicitly.
- Known incompatible task/backend/effort/context/request setting: refuse before HTTP/subprocess; no alternate selection used. Domain/root fixtures drive table negatives without forging real production facts.
- Service busy/failure and uncertain original agent cause: P2/P3 root fault injection supplies deterministic HTTP 429/5xx/transport and wrapper tests; do not induce a real outage or relabel skipped cases as live evidence.
- Scan MCP responses, persisted node errors/traces and actual server logs with successful reads; assert no key/auth tokens. Never serialize raw request arguments containing the connection key into the acceptance artifact.
