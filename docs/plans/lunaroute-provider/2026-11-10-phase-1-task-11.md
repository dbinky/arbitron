**Interfaces:**

```yaml
items:
  LR-01: # exactly LR-01 through LR-08, no missing/extra ids
    title: Hosted destination and dialect/auth contract
    status: unresolved # unresolved | verified | escalated
    evidence: [] # existing repo-relative source/observation paths; external URLs go inside source notes
    escalation: Confirm hosted destination and auth/path per required operation
    applied_to: [] # file:symbol references where verified facts are used
```

Initialize all eight items as unresolved with the specific missing-input/decision text above. A verified item needs nonempty existing evidence and nonempty applied_to; unresolved/escalated items need actionable escalation text. P4-T7 adds the completed acceptance artifact gate. Empty/missing register content fails even when release gating is not requested.

Shared helpers in `test/lunaroute`, package `lunaroute_test`:

- `type registerItem struct { Title, Status string; Evidence []string; Escalation string; AppliedTo []string }`, `type register struct { Items map[string]registerItem }` with matching YAML tags.
- `loadRegister(t *testing.T) register`, `validateRegister(r register) []string`, `repoRoot(t *testing.T) string`, `evidenceDir(t *testing.T) string`.
- `liveKey(t *testing.T) string`: local explicit skip when missing; release mode fails missing input.
- `writeObservation(t *testing.T, key, name string, v any) string`: JSON encoder, reject literal key/auth tokens and secret-bearing content **before writing**; basename-only output inside observations; create owner-only directory/file; return repo-relative path. Unit tests use a pure validation helper and injected writer to assert no write on error. Do not let a `require` failure print raw secret-bearing payloads.
- `const hostedRoot`: sourced from LR-01 verification, matching P1-T1 helper.
- `liveClient() *http.Client`: bounded timeout and `CheckRedirect -> http.ErrUseLastResponse`.
- `shape(body []byte) map[string]string`: JSON field/type schema only; no response values/messages. Nested listing-id/error-code validation has separate LR-04 tests; top-level `data:array` alone proves too little.

- [ ] **Step 2: Strict-TDD register and observation framework**

Write named RED tests before implementing helpers:

| Category | Tests and assertions |
|---|---|
| Happy | `TestRegisterSchema`: complete eight-item unresolved register with escalation text is valid as pending, never release-ready. |

Run `go test ./test/lunaroute -run 'Register|Observation|ReleaseGate' -count=1` RED, implement schema/helpers, run GREEN and refactor. `TestReleaseGate` must call schema validation itself before statuses, not rely on another test being selected.

- [ ] **Step 3: Direct live gateway contract experiment**

Implement `TestLiveGatewayContract` independent of Arbitron adapters. Use context-bounded, response-capped, no-redirect raw HTTP. Require a verified explicit model per dialect from author input/source facts, never automatically pick the first model. For each planned credential sink verify the **actual auth and inference path**:

1. GET models with the supported listing auth → validate complete recorded envelope and nonempty ids (or accurately recorded empty availability, which cannot satisfy selected live profiles).
2. POST chat-completions with Bearer and an explicit reviewed model → successful terminal content.
3. POST Messages using the auth/header that Claude Code actually emits → successful content/terminal status (x-api-key need not work on listing if only Messages uses it).
4. POST Responses with codex's actual credential header → successful terminal response.
5. Invalid key produces the known credentials verdict; auth/path differences that are not known remain uncertain. Do not require both auth headers on every endpoint without service evidence.

Record status, dialect, path, auth **header name**, model/response spelling and safe schema/terminal booleans, never key/body messages. Assert I/O/decode/size errors; do not ignore `io.ReadAll` failures. A model-list success alone cannot verify LR-01's three inference dialects. P2-T8 owns LR-04 code capture, P3/P4 prove tool and helper runtime behavior.

Replace temporary `ships empty` assertions after population; never keep empty maps as a permanent acceptance criterion. Root tests load distinctive fixture facts separately, and live release tests load the actually deployed default/override. Register verified status requires both evidence and runtime application.
