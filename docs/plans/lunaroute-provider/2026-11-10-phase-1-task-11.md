Status rules:
- `decided`: the contract is fixed by the decisions doc; verification is pending.
- `verified`: nonempty existing evidence and nonempty `applied_to`.
- `escalated`: a verification contradicted the contract. Escalation text names the contradiction, and the decision's On-failure rule has been applied.
- The release gate accepts only `verified`.

If a static fact or spelling cannot be found in LunaRoute's docs, record it as `unknown` and apply the LR-02/LR-03 On-failure rule. Do not stop unrelated work.

Never hardcode unknown pi reasoning as false or infer it from nonempty efforts. No automated recommendation/fallback or expansion to new modalities. Do not write shared harness auth/config. Observation files and console output must be credential-free.

Initialize all eight items as `decided` with a `decision` reference into the decisions doc and the source notes this task writes. A `decided` item needs a nonempty `decision` reference; a `verified` item needs nonempty existing evidence and nonempty `applied_to`; an `escalated` item needs actionable escalation text. P4-T7 adds the completed acceptance artifact gate. Empty/missing register content fails even when release gating is not requested.

Shared helpers in `test/lunaroute`, package `lunaroute_test`:

- `type registerItem struct { Title, Status, Decision string; Evidence []string; Escalation string; AppliedTo []string }`, `type register struct { Items map[string]registerItem }` with matching YAML tags.
- `loadRegister(t *testing.T) register`, `validateRegister(r register) []string`, `repoRoot(t *testing.T) string`, `evidenceDir(t *testing.T) string`.
- `liveKey(t *testing.T) string`: local explicit skip when missing; release mode fails missing input.
- `writeObservation(t *testing.T, key, name string, v any) string`: JSON encoder, reject literal key/auth tokens and secret-bearing content **before writing**; basename-only output inside observations; create owner-only directory/file; return repo-relative path. Unit tests use a pure validation helper and injected writer to assert no write on error. Do not let a `require` failure print raw secret-bearing payloads.
- `const hostedRoot = "https://gw.lunaroute.com"`: the LR-01 decided root, asserted equal to `provider.LunaRouteHostedRoot`.
- `liveClient() *http.Client`: bounded timeout and `CheckRedirect -> http.ErrUseLastResponse`.
- `shape(body []byte) map[string]string`: JSON field/type schema only; no response values/messages. Nested listing-id/error-code validation has separate LR-04 tests; top-level `data:array` alone proves too little.

- [ ] **Step 3: Direct live gateway contract experiment**

Implement `TestLiveGatewayContract` independent of Arbitron adapters. Use context-bounded, response-capped, no-redirect raw HTTP. Require a verified explicit model per dialect from author input/source facts, never automatically pick the first model. For each planned credential sink verify the **actual auth and inference path**:

1. GET models with the supported listing auth → validate complete recorded envelope and nonempty ids (or accurately recorded empty availability, which cannot satisfy selected live profiles).
2. POST chat-completions with Bearer and an explicit reviewed model → successful terminal content.
3. POST Messages with `Authorization: Bearer` (what Claude Code emits from `ANTHROPIC_AUTH_TOKEN`, LR-01/LR-05 decided) plus `anthropic-version` → successful content/terminal status.
4. POST Responses with `Authorization: Bearer` (codex `env_key`) → successful terminal response.
5. Invalid key produces `INVALID_API_KEY`/401 → credentials verdict. Every request uses Bearer only (LR-01); `x-api-key` and `LUNAROUTE-API-KEY` are not exercised.
6. If any step fails, apply the LR-01 On-failure rule: release mode fails, the register item becomes `escalated`, and constants are not edited.

Record status, dialect, path, auth **header name**, model/response spelling and safe schema/terminal booleans, never key/body messages. Assert I/O/decode/size errors; do not ignore `io.ReadAll` failures. A model-list success alone cannot verify LR-01's three inference dialects. P2-T8 owns LR-04 code capture, P3/P4 prove tool and helper runtime behavior.
