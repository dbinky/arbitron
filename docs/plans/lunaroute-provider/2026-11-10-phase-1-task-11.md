Status rules:
- `decided`: the contract is fixed by the decisions doc; verification is pending.
- `verified`: nonempty existing evidence and nonempty `applied_to`.
- `escalated`: a verification contradicted the contract. Escalation text names the contradiction, and the decision's On-failure rule has been applied.
- The release gate accepts only `verified`.

If a static fact or spelling cannot be found in LunaRoute's docs, record it as `unknown` and apply the LR-02/LR-03 On-failure rule. Do not stop unrelated work.

Never hardcode unknown pi reasoning as false or infer it from nonempty efforts. No automated recommendation/fallback or expansion to new modalities. Do not write shared harness auth/config. Observation files and console output must be credential-free.
