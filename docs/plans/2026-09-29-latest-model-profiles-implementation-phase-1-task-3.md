## Data producers and composition-root wiring

Actual workflow `NodeConfig.ModelProfile` values loaded in `TriggerWithDepartment` produce the distinct required alias set, including the spawn input preparer's alias. Capture aliases from the same serialized workflow that will execute; include all branches, loop nodes and interactive nodes. Version resolution runs under the shared execution read lease so routing/policy edits cannot change between profile capture and specific-version validation. After the lease ends, the returned immutable model map is persisted unchanged with the instance before enqueue. Cache's coherent profiles produce requested models; P3T1 recognizes supported fixed IDs and rejects mutable aliases; the D8 exception below preserves native pinned-only configured IDs without an immutability claim. Snapshot adapter reads workflow-scoped route metadata with ConnectionStore.Get (no key reveal) under P3T3 execution read lease and constructs P3T1 VersionRequest from the captured Profile and non-secret metadata; it must not resolve Model again from a different cache generation. Instance `Create` persists pins/version together with workflow/variables before enqueue. P1T4 supplies the snapshotter at `initDomain`.
