## Fixed Previously

- **FA#1 Pass 1 — nil Approver default-deny not tested.** The `fakeMCPSession.Start` correctly records a zero `approvalDecision{Allow:false}` when `cfg.Approver` is nil (fail-closed by Go zero value), but this was not exercised. Added `TestFakeMCPSession_Edge_NilApproverDefaultDeny` to verify the fail-closed property explicitly.
- **FA#1 Pass 2 — nil-safety contract undocumented at port level.** `turnConfig.Approver` and `approvalFunc` type comment did not state that nil must be treated as default-deny. Added a one-line clarification to both so transport implementations know to nil-check before calling, not panic.
- **FA#1 Pass 2 — FAILURE test did not assert no-Done-after-failure.** `TestFakeMCPSession_Failure_TurnFailedSurfacesError` verified `turnFailed` is returned but did not assert that a subsequent `Next` call yields `errStreamDone` (not `turnDone`). Added the assertion to prove a failed turn never silently becomes a success.
- **FA#2 Pass 1 — single-approval SUCCESS test insufficient.** No test verified all N approval requests from a mixed scenario (allow+deny) are each delivered to the approver in order, with each decision recorded separately. Added `TestFakeMCPSession_Success_MultipleApprovalsAllDeliveredInOrder` to cover this gap and prove a denial doesn't terminate the event stream.
- **FA#2 Pass 2 — no compile-time check for fakeTurnStream implementing turnStream.** The fake's stream type was only implicitly checked via the `Start()` return type. Added `var _ turnStream = (*fakeTurnStream)(nil)` alongside the existing mcpSession check so any future interface expansion is caught at the test-seam level.
- **FA#3 Pass 1 — compatible probe + launch fails was untested.** `mcpStdioSession.Start` has three fail-closed paths (empty WorkDir, incompatible probe, compatible probe but exec fails). Only the first two were tested. Added `TestMCPStdioSession_Error_LaunchFailsAfterCompatibleProbe` using `multiRunner{compatibleProbe()}` to exercise the third path: probe passes, but `/nonexistent/codex mcp-server` fails at OS exec time.
- **FA#3 Pass 1 — WorkDir guard ordering not asserted.** `TestMCPStdioSession_Error_EmptyWorkDirFailsClosed` verified the error sentinel but did not assert that the runner was never called. Added `assert.False(t, runner.runCalled)` to prove the WorkDir guard fires before the probe, not after.
- **FA#3 Pass 2 — malformed notification payload fail-closed path untested.** `mapNotification` maps a decode error to `(turnFailed, ok=true)` — fail-closed so a corrupted mcp frame never silently drops from the stream. This path had no test. Added `TestMapNotification_Error_MalformedPayloadFailsClosed` using a non-marshalable channel value in `AdditionalFields` to force the decode error and assert `turnFailed` is returned (not a silent drop).
- **FA#4 Pass 1 — conversationID thread_id fallback untested.** `conversationID` prefers `conversation_id` and falls back to `thread_id` for session resume, but the fallback path had no test. Added `TestMapNotification_Edge_TurnCompletedWithThreadIDFallback` to assert that a `turn.completed` with only `thread_id` still produces a `turnDone` with the thread id as `SessionID`.
- **FA#4 Pass 1 — agentText top-level message fallback untested.** `agentText` falls back to `ev.Message` when `item.text` is absent — if broken, tokens would be silently dropped. Added `TestMapNotification_Edge_AgentMessageFallsBackToTopLevelMessage` to exercise the fallback path.
- **FA#4 Pass 1 — mapApprovalRequest both-present precedence untested.** When both `command` and `paths` are present (ambiguous payload), command takes precedence. Without a test, removing the command-first switch case would silently change behavior. Added `TestMapApprovalRequest_Edge_CommandTakesPrecedenceOverPaths` to pin the precedence.
- **FA#4 Pass 2 — turnError empty-message fallback untested.** A `turn.failed` or `error` event with neither a nested error message nor a top-level message produces `fmt.Errorf("codex turn failed: turn failed")` via the fallback string. Without a test, a refactor that removed the fallback would silently produce empty-cause failures. Added `TestMapNotification_Edge_TurnFailedNoMessageFallback` to assert the error is always non-empty.
- **FA#5 Pass 1 — SPIKE constants not value-pinned.** All mapper tests use constants in both input and expected output, so if a constant drifts from its intended string value the mappers silently use the wrong value and the mapper tests still pass. Added `TestSpikeConstants_ReusedExecVocabularyArePinned` (pins `agent_message`/`turn.completed`/`turn.failed`/`error` against `parse.go` literals) and `TestSpikeConstants_AssumedPostureConstantsArePinned` (pins `read-only`/`on-request`/`conversation_id`).
- **FA#7 Pass 2 — `..`-escapes above workDir not tested.** The existing table only tested escapes staying within workDir (e.g. `"docs/../domain/x.go"`). A path like `"../../etc/passwd"` or `"../sibling-repo/docs/x.md"` climbs above workDir; verified correct denial and added both cases to `TestWithinRoot`.
- **FA#7 Pass 1 — `withinRoot` only tested with root=`"docs"`.** All 16 `TestWithinRoot` cases use the same fixed root. A deeper `writableRoot` (e.g. `"docs/superpowers"`) must narrow correctly: `docs/specs/a.md` is in docs/ but NOT in `docs/superpowers/`. Added `TestWithinRoot_Edge_DeeperRoot_NarrowsSubtree` to verify multi-level roots and prefix-sibling exclusion.
- **FA#6 Pass 2 — denial Reason assertions were weak (NotEmpty only).** For the canonical guardrail scenarios (`..`-escape, absolute-outside, mixed docs+source patch), the Reason must identify the offending path so the operator's slog trace is actionable. Strengthened three adversarial tests to `assert.Contains(t, d.Reason, offendingPath)`.
- **FA#6 Pass 1 — empty WritePaths slice allows vacuous truth.** `decidePatch([]string{})` without the `len(paths) == 0` guard would range over nothing and return `Allow: true`. Added `TestDecide_Patch_Edge_EmptyWritePathsSlice_Denied` to pin the guard.
- **FA#5 Pass 2 — security-critical arg KEY strings not pinned.** `TestStartToolRequest_Happy_FreshConversation` uses constants in both the map build and the lookup (`args[codexArgSandboxMode]`), so a wrong KEY string (e.g. `codexArgSandboxMode = "sandbox"`) passes that test — the constant-keyed lookup finds the value at the same wrong key. A wrong key silently drops the posture config: codex falls back to its default (possibly read-write or no-approval) mode. Added `TestSpikeConstants_SecurityPostureArgKeysPinned` to pin `sandbox_mode`/`approval_policy`/`codex`/`codex/event`.

- **FA#8 Pass 2 — `turnFailed` error wrapping not asserted in either failure test.** `StreamChat` and `Chat` both format the failure as `fmt.Errorf("...: %w", ev.Err)` so callers can `errors.Is(err, specificErr)` to identify rate-limit / auth / model errors. Neither `TestInteractive_StreamChat_TurnFailed_ErrorNoDone` nor `TestInteractive_Chat_TurnFailed_HardError` verified this — they used only `assert.Error`. Changing `%w` to `%v` would silently break error identification without failing those tests. Strengthened both with `assert.ErrorIs` against the sentinel error.
- **FA#8 Pass 1 — `Chat` `!sawDone` hard-error path untested.** `Chat` has a `sawDone` guard: if the turn stream ends with `errStreamDone` but no `turnDone` was received, it returns `"turn ended without completion"` rather than a silent empty `ChatResponse`. This path had no test. Added `TestInteractive_Chat_NoTerminalDone_HardError` using `errStreamSession{nextErr: errStreamDone}` to exercise the fail-closed guard.

- **FA#9 Pass 1 — `Chat` transport-error hard-error path untested.** `StreamChat` has `TestInteractive_StreamChat_TransportError_ErrorNoDone` proving a non-sentinel stdio break returns a terminal Error chunk with no Done. The symmetric `Chat` path (`return nil, fmt.Errorf("...: %w", nerr)` at line 263 of `interactive_provider.go`) is only exercised via context.Canceled; a plain transport error like `errors.New("stdio broke")` is untested. Added `TestInteractive_Chat_TransportError_HardError`.

- **FA#9 Pass 2 — `approvalSummary` security property untested.** `approvalSummary` produces the slog "summary" field in `tracingApprover`. It must never include `req.Reason` (codex's human-readable explanation, which may contain prompt-derived content); only the structural facts (argv or paths) are safe to log. All three branches (command / write / unknown) are untested; if someone added `+ req.Reason` to any branch, no test would catch the leak. Added `TestApprovalSummary_NeverLogsRequestReason` to directly verify the security property across all three paths.

- **FA#10 Pass 1 — spurious `turnDone` after `turnFailed` not proven suppressed.** The `failed` flag in `StreamChat` drains all subsequent events after a `turnFailed` — including a spurious `turnDone` that a misbehaving transport might emit. Without a test, someone could accidentally remove the `if failed { continue }` guard and a post-failure Done would escape as a clean chunk, silently overriding the failure. Added `TestInteractive_StreamChat_TurnDoneAfterTurnFailed_NoDoneChunk` to prove the guard holds end-to-end.
- **FA#10 Pass 2 — double-error on turnFailed + transport error not proven suppressed.** When a transport error arrives after `turnFailed` (while `failed=true`), the `if !failed` guard on the transport-error send path suppresses the second `sendChunk` call — but no test verified only ONE error chunk escapes the channel. Removing the `!failed` guard would cause a double-error (turn-failure chunk + transport-error chunk), breaking single-terminal-event consumer contracts. Added `TestInteractive_StreamChat_TransportErrorAfterTurnFailed_SingleErrorOnly` to pin the guard and prove exactly one error chunk arrives (the turn-failure one).

- **FA#11 Pass 2 — `RevealKey` never-called invariant untested on error paths.** Both `TestInteractive_StreamChat_EmptyWorkDir` and `TestInteractive_Chat_EmptyWorkDir` used `codexBinding(..., nil)` — no sentinel tracking. If `startTurn` were changed to call `RevealKey` before (or between early guards), neither error-path test would catch it. Strengthened both tests with `&revealed` and `assert.False(t, revealed, ...)` to prove the invariant holds on error paths, not just happy-path completions.
- **FA#11 Pass 1 — `Chat` happy path never asserted `RevealKey` is not called.** `TestInteractive_StreamChat_HappyPath` already tracked `revealed` and verified `RevealKey` was never called. `TestInteractive_Chat_HappyPath` passed `nil` for the sentinel pointer, so a future change that added `p.binding.RevealKey(ctx)` inside the `Chat` fold or `startTurn` would go undetected. Threaded `&revealed` into the Chat happy path and added the `assert.False(t, revealed, ...)` assertion.

- **FA#12 Pass 2 — spawn-per-turn invariant not proven by any test.** `InteractiveProvider.newSession` is called once per `StreamChat`/`Chat` invocation, but no test verified the factory is called anew each turn rather than caching. A `sync.Once`-style cache would reuse the first turn's Approver (stale WorkDir-scoped policy) and share an exhausted stream — silently breaking session isolation. Added `TestInteractive_SpawnPerTurn_FreshSessionEachStreamChat` to assert the factory call count equals the number of turns.
- **FA#12 Pass 1 — Chat fold resume plumbing untested.** `TestInteractive_StreamChat_ResumeID` proves `req.SessionID`→`turnConfig.ResumeID` for the StreamChat path, but there was no symmetric test for Chat. A refactor that bypassed `startTurn` for Chat, or omitted `ResumeID: req.SessionID` in a Chat-specific path, would go undetected. Added `TestInteractive_Chat_ResumeID` to assert both the forward flow (`ResumeID` in `gotCfg`) and the back-out (`resp.SessionID` from the terminal done event).

- **FA#13 Pass 2 — opencode rejection bypassable via defaultBackend floor (untested).** The `agentStreamFor` function explicitly rejects opencode before the map lookup, but there was no test that the rejection holds when opencode is reached VIA the `defaultBackend` floor (i.e., `Backend == ""` and `defaultBackend == "opencode"`). A misconfigured deployment with `defaultBackend = "opencode"` would silently route empty-backend bindings through the explicit rejection check. Without this test, removing the explicit opencode check would degrade the error message but not break existing tests. Added `TestInteractiveStreamSelector_AgentKind_OpencodeDefaultBackend_FailsClosed` to verify the opencode rejection fires on the floored backend too.
- **FA#13 Pass 1 — empty-Binding.Model composition-root pattern untested.** The composition root constructs `NewInteractiveProvider(InteractiveConfig{...})` WITHOUT setting `Binding.Model` — the engine injects the model per-request via `ChatRequest.Model`. `TestInteractive_StreamChat_RequestModelOverridesBinding` tests `req.Model` overriding a non-empty binding model, but not the `binding.Model == ""` case the composition root depends on. Added `TestInteractive_StreamChat_EmptyBindingModel_UsesRequestModel` to prove `req.Model` is used as the sole model source when `Binding.Model` is empty.

- **FA#15 (Paired) — session-id back-out from transport seam untested.** `TestInteractive_StreamChat_ResumeID` proved the forward flow (`req.SessionID → turnConfig.ResumeID`) but did NOT assert the back-out (`doneEv.SessionID → ChatChunk.SessionID`). A provider that reflected the resume id instead of passing through the transport's new session id would pass all existing tests. Added `TestInteractive_StreamChat_SessionIDRoundTrip` with distinct input/output ids (`old-conv-id` in → `new-conv-id` out) to prove both directions of the transport seam.
- **FA#14 (Paired) — mixed-decision multi-approval turn untested at provider level.** All provider-level approval tests had exactly ONE approval request per turn. There was no test proving that with multiple mixed decisions (some allowed, some denied) the provider: (a) adjudicates each independently, (b) does not abort the stream on a denial, and (c) reaches a clean Done with no Error chunk. Added `TestInteractive_Approval_MixedDecisions_StreamReachesDone` with a 3-approval sequence (allow/deny/allow) to pin the integration seam.
