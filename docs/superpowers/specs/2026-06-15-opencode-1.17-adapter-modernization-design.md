# opencode 1.17.x adapter modernization — design

**Date:** 2026-06-15
**Status:** Approved (brainstorm) — pending spec review
**Area:** `adapter/opencode`

## Problem

The `adapter/opencode` agent backend was verified against `opencode-ai` **0.4.x** (`args.go`: "Verified against opencode-ai >= 0.4.0"). The available modern binary is **1.17.7**, whose `run` CLI contract diverged from 0.4.x. Two breakages were observed live in a `feature-pipeline-v2` run (profile `coder-ds4`, connection `ollama-cloud`, model `deepseek-v4-flash`):

1. **Permission flags removed.** The adapter emits `--allowed-tools <csv>` (scoped) / `--allow-all-tools` (open). opencode 1.17.7 has **neither**; it dumps usage and exits non-zero. Modern opencode expresses per-tool permissions via config (`permission` block / agent), with `--dangerously-skip-permissions` for headless approval. Tool names also changed to lowercase (`read`, `write`, `edit`, `grep`, `glob`, `bash`, …).
2. **Base-URL env vars ignored on the routing path.** The adapter sets per-provider base-URL env vars (`OLLAMA_BASE_URL`, `OPENAI_BASE_URL`, …). opencode 1.17.7 does **not** honor these on its `@ai-sdk/*` model-routing path; base URLs must come from a config `provider` block. Cloud Ollama is a **built-in provider literally named `ollama-cloud`** (fixed `https://ollama.com/v1`, key `OLLAMA_API_KEY`) — but the adapter maps `ollama-cloud → ollama` and relies on `OLLAMA_BASE_URL`, so it would silently target *local* Ollama.

A prior hotfix (commit `b6a056f`) added `providerIDMap["ollama-cloud"] = "ollama"` to clear the launch-time "no env mapping" error. That fix was correct for the *old* contract but is **wrong for 1.17.x** and is superseded by this design (`ollama-cloud → ollama-cloud`).

## Decision summary

- **Scope:** Full modernization — every provider opencode routes (anthropic, openai, litellm, openrouter, azure, amazon-bedrock, ollama-local, ollama-cloud), not just the `coder-ds4` path.
- **Min version floor:** `>= 1.17.0` (pinned to the verified line; fail-closed below it).
- **Config injection:** `OPENCODE_CONFIG_CONTENT` env var (inline JSON). No file written → no collision with a target repo's own `opencode.json`, no worktree artifact. Secrets stay in the subprocess env and are referenced from the JSON via `{env:VAR}` interpolation.

## Architecture

Each mission (`Provider.RunAgent`) builds three coordinated outputs from the resolved binding + posture, then launches one `opencode run`:

1. **argv:** `run <prompt> -m <opencodeId>/<model> --dangerously-skip-permissions --format json`
2. **env:** credential variable(s) only — `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` / `OPENROUTER_API_KEY` / `OLLAMA_API_KEY` / `AZURE_API_KEY` / AWS quartet. **Never** the base URL, **never** in argv or logs. (Reuses the existing `procenv.CredentialEnv` fail-closed skeleton + bedrock AWS-quartet builder.)
3. **`OPENCODE_CONFIG_CONTENT`:** a generated JSON document `{ "$schema": "https://opencode.ai/config.json", "provider"?: {...}, "permission": {...} }`.

Fail-closed ordering is unchanged: WorkDir guard → build argv (unknown provider / empty model fails closed) → build env + config (RevealKey / config failure fails closed) → memoized version probe → run. No partial-env launch.

### Provider routing (verified against the 1.17.7 binary)

Replaces `providerIDMap` (`provider_id.go`) and `providerEnvVarTable` (`env_providers.go`) with one per-provider descriptor: `{ opencodeID, credEnv, npmPackage, builtInBaseURL, needsProviderBlock }`.

| arbitron provider (canonical) | opencode `-m` id | credential env | `provider{}` config block |
|---|---|---|---|
| `anthropic-api` | `anthropic` | `ANTHROPIC_API_KEY` | only when binding.BaseURL set (npm `@ai-sdk/anthropic`) |
| `openai` | `openai` | `OPENAI_API_KEY` | only when binding.BaseURL set (npm `@ai-sdk/openai`) |
| `litellm` | `litellm` (custom id) | `OPENAI_API_KEY` | **always** — `@ai-sdk/openai-compatible` + `options.baseURL` |
| `openrouter` | `openrouter` | `OPENROUTER_API_KEY` | only when binding.BaseURL set |
| `azure` | `azure` | `AZURE_API_KEY` | **always** — `options.resourceName`/`baseURL` + `apiVersion` (npm `@ai-sdk/azure`) |
| `bedrock` | `amazon-bedrock` | AWS quartet (`AWS_REGION`, not `AWS_DEFAULT_REGION`) | only for `options.region`/`profile` override |
| `ollama` (local) | `ollama` (custom id) | — (keyless) | **always** — `@ai-sdk/openai-compatible` + `options.baseURL` |
| `ollama-cloud` | `ollama-cloud` (built-in) | `OLLAMA_API_KEY` | **no** — built-in, fixed `https://ollama.com/v1` |

Rule: emit a `provider.<id>` block when the provider has **no built-in** (litellm, ollama-local) OR the binding carries a **custom BaseURL** that overrides a built-in default OR the provider needs structured options (azure resourceName/apiVersion, bedrock region). When emitted, `options.apiKey` uses `"{env:<VAR>}"` so the secret stays in env. Otherwise rely on the built-in + the credential env var alone.

The domain `provider.Canonicalize` is unchanged: `ollama-cloud` stays canonically distinct from `ollama` (the url_policy loopback/SSRF boundary still holds — only local `ollama` earns the loopback carve-out). The new descriptor table keys on the canonical id and is the single opencode-side vocabulary shared by argv (`-m`), env, and config generation.

### Permissions

`posture.go` resolves the same two postures; they now translate to a config `permission` block instead of CLI flags:

- **Scoped allowlist** (e.g. `coder-ds4`: `Read,Write,Edit,Grep,Glob,Bash`) → `{"*":"deny", "read":"allow", "write":"allow", "edit":"allow", "grep":"allow", "glob":"allow", "bash":"allow"}` (deny-all, then allow the mapped set).
- **Allow-all** → `{"*":"allow"}`.

Tool-name mapping (Claude → opencode): `Read→read, Write→write, Edit→edit, Grep→grep, Glob→glob, Bash→bash, LS→list, WebFetch→webfetch, WebSearch→websearch, TodoWrite→todowrite, Task→task`. Names with **no 1.17.7 equivalent** (`MultiEdit`, `TodoRead`) are dropped and logged once (not silently). An allowlist entry that maps to nothing and yields an empty effective allowlist fails closed (no tool-less silent run).

`--dangerously-skip-permissions` is always passed: it auto-approves `ask` pseudo-permissions (`external_directory`, `doom_loop`, …) so a headless run never blocks on a missing TTY, and (verified) it does **not** override explicit `deny` entries — the deny-list remains authoritative.

### Output parsing

`parse.go` currently parses 0.4.x text output. Switch to `--format json` and parse the structured event stream into the existing `AgentResult` shape (summary, steps, tokens-out). JSON is the stable headless contract; the text format is not.

### Version gate

`version.go`: `minOpencodeVersion = "1.17.0"`, with a comment recording the 0.4.x→1.17.x contract break (permission flags removed, base-URL via config, JSON output). The probe logic (`probeVersion`, semver parse/compare) is unchanged.

## Files touched

- `provider_id.go` — replace map with the 1.17.x descriptor table (or fold into a new `providers.go`).
- `env_providers.go` — credential env table aligned to 1.17.x credential vars (azure `AZURE_API_KEY`, bedrock quartet incl. `AWS_REGION`); drop base-URL vars.
- `env.go` — build credential env only (no base-URL var); keyless ollama-local path retained.
- `config.go` *(new)* — generate the `OPENCODE_CONFIG_CONTENT` JSON (provider block + permission block) from binding + posture.
- `args.go` — argv: `-m`, `--dangerously-skip-permissions`, `--format json`; remove `--allow-all-tools`/`--allowed-tools`.
- `posture.go` — unchanged resolution; consumed by `config.go`.
- `parse.go` — JSON event-stream parsing.
- `version.go` — floor bump + comment.
- `provider.go` (`RunAgent`) — thread `OPENCODE_CONFIG_CONTENT` into the subprocess env.
- Tests for each, plus a live `coder-ds4` smoke validation via a pipeline re-run.

## Testing

- **Hermetic unit tests** via the existing fake `CommandRunner`: per provider, assert (a) argv (`-m <id>/<model> --dangerously-skip-permissions --format json`), (b) env (credential var present with the secret; **no** base-URL var; AWS quartet for bedrock), and (c) the generated `OPENCODE_CONFIG_CONTENT` JSON (provider block present/absent per the rule; `options.apiKey` uses `{env:VAR}`; permission block matches the posture with mapped tool names).
- **Security assertions:** secret never in argv; base URL never in argv/logs; deny-all-then-allow for scoped postures; unknown/empty-mapped allowlist fails closed.
- **JSON parse tests:** fixture event streams → `AgentResult`.
- **Live smoke:** re-run `feature-pipeline-v2` (spec_only=false) and confirm `impl-task` (`coder-ds4` → `ollama-cloud` → `deepseek-v4-flash`) executes end-to-end.

## Out of scope / follow-ups

- Session resume (`-c/--session`) — the adapter remains single-shot per mission (unchanged).
- Token-by-token streaming — still whole-message (unchanged).
- The base-URL-via-env nuance is treated as **unsupported** (inferred-negative from binary inspection); if a future need arises, a one-line smoke test can confirm whether `@ai-sdk/*` honors `*_BASE_URL` and the descriptor table can switch that provider back to env.

## Risks

- opencode is fast-moving; pinning to `>= 1.17.0` plus a generated-config approach reduces churn but a future major could shift the config schema. Mitigation: the config generation is centralized in one `config.go` and the `$schema` URL is pinned.
- `bedrock` `AWS_SESSION_TOKEN` is not in opencode's declared env list (SDK credential chain likely picks it up) — flagged; bedrock-via-opencode is not on the immediate validation path.
